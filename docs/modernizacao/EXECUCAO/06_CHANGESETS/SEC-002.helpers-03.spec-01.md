## 1. Motivação

`SEC-002.tests-01 §3` e `SEC-002.plan-01 §4` referenciam três dependências que `helpers-02` não entrega:

1. **overloads sem `uid`** — políticas RLS ficam mais legíveis usando `public.user_in_obra(obra_id)` do que `public.user_in_obra(auth.uid(), obra_id)`;
2. **`user_has_setor(_setor text)`** — lote D (DP/financeiro) e Lote B (registries de setor) precisam checar setor funcional sem depender de `has_role(app_role)`, que hoje só cobre `gm`;
3. **`user_can_approve(_solicitacao uuid)`** — caso `segregation` do lote D (`solicitacoes_financeiras`, `controle_despesas`): garante `solicitante_id <> auth.uid()` no lado server.

## 4. Assinaturas canônicas

```sql
-- 4.1 overloads sem uid (delegam para o overload de helpers-02)
create or replace function public.user_in_empresa(_empresa uuid)
returns boolean language sql stable security definer set search_path = public
as $$ select public.user_in_empresa(auth.uid(), _empresa) $$;

create or replace function public.user_in_obra(_obra uuid)
returns boolean language sql stable security definer set search_path = public
as $$ select public.user_in_obra(auth.uid(), _obra) $$;

create or replace function public.user_in_board(_board uuid)
returns boolean language sql stable security definer set search_path = public
as $$ select public.user_in_board(auth.uid(), _board) $$;

create or replace function public.user_in_card(_card uuid)
returns boolean language sql stable security definer set search_path = public
as $$ select public.user_in_card(auth.uid(), _card) $$;

-- 4.2 setor funcional
create or replace function public.user_has_setor(_user uuid, _setor text)
returns boolean language sql stable security definer set search_path = public
as $$
  select public.current_is_gm()
      or exists (
        select 1 from public.user_setores us
        where us.user_id = _user and us.setor = _setor
      )
$$;

create or replace function public.user_has_setor(_setor text)
returns boolean language sql stable security definer set search_path = public
as $$ select public.user_has_setor(auth.uid(), _setor) $$;

-- 4.3 segregation of duties
create or replace function public.user_can_approve(_solicitacao uuid)
returns boolean language sql stable security definer set search_path = public
as $$
  select public.current_is_gm()
      or exists (
        select 1 from public.solicitacoes_financeiras s
        where s.id = _solicitacao
          and s.solicitante_id is distinct from auth.uid()
          and public.user_has_setor(auth.uid(), 'financeiro')
      )
$$;
```

## 8. Anti-recursão

Todas as funções são `security definer` + `set search_path = public` + `stable`. Nenhuma faz `select` em tabela com policy que **consulta a própria função** (ver `SEC-002.helpers-01 §I-H4`). `user_can_approve` só toca `solicitacoes_financeiras` para ler `solicitante_id`; a policy do lote D usará `user_can_approve` em `UPDATE`, nunca em `SELECT` sobre a mesma linha.
