# OPS-001.b — CI com lint e typecheck da Onda 1

**Onda:** 1 · **Categoria:** Operação/CI  
**Cisão:** OPS-001 → OPS-001.a (gate mínimo, Onda 0) · **OPS-001.b** (gate completo pós-QC-001/QC-002)  
**Relacionado:** QC-001, QC-002, TST-004, G-02, D-08, D-13

## Problema

Após a Onda 0, o CI já existia como proteção mínima, mas a conclusão da Onda 1 exige que o gate oficial incorpore explicitamente a régua de lint e o typecheck estrito definido por QC-001/QC-002.

## Ação

Workflow `.github/workflows/ci.yml` ajustado para o gate da Onda 1:

1. `bun install --frozen-lockfile`.
2. Verificação de pinagem `xlsx` em `0.20.x`.
3. `bun run lint` como gate bloqueante.
4. `bun run typecheck` como gate bloqueante, usando `tsconfig.qc001.json` com `strict`, `strictNullChecks` e `noImplicitAny` em `src/lib/**` e `src/services/**`.
5. `bun run test` como gate bloqueante.
6. `bun run test:coverage` como snapshot não bloqueante, preservando TST-004/D-13 sem impor threshold nesta onda.
7. `bun run build` como gate bloqueante.

## Fora de escopo

- Threshold obrigatório de cobertura — a baseline ainda é baixa e segue como insumo incremental.
- Gate de tamanho de bundle.
- Upload de source maps/artefatos de release.

## Critérios de aceite

- (a) CI contém lint bloqueante ✅
- (b) CI contém typecheck bloqueante via script oficial do projeto ✅
- (c) Medição de cobertura entra no pipeline sem bloquear merge ✅
- (d) Ordem preserva install → qualidade → regressão → build ✅

## Discoveries

- **D-18:** o typecheck do CI passa a usar o mesmo contrato local de QC-001 (`bun run typecheck`), evitando divergência entre gate local e remoto.
- **D-19:** cobertura permanece não bloqueante nesta entrega; tornar threshold obrigatório exige plano próprio de aumento de cobertura.
