**Caminho de destino:** `.github/workflows/sec002-pr-checklist.yml`  
**Encoding:** UTF-8, LF, sem BOM.  
**Runtime:** GitHub Actions + Node 20.  
**Segredos:** nenhum.

```yaml
name: sec002-pr-checklist

on:
  pull_request:
    types: [opened, edited, synchronize, reopened, ready_for_review]

permissions:
  contents: read
  pull-requests: read

concurrency:
  group: sec002-pr-checklist-${{ github.event.pull_request.number }}
  cancel-in-progress: true

jobs:
  validate:
    if: contains(github.event.pull_request.title, '[SEC-002][apply:')
    runs-on: ubuntu-latest
    timeout-minutes: 8
    env:
      PR_TITLE: ${{ github.event.pull_request.title }}
      PR_BODY: ${{ github.event.pull_request.body }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-node@v4
        with:
          node-version: "20"

      - name: Collect changed files
        run: |
          git diff --name-only origin/${{ github.base_ref }}...HEAD > /tmp/sec002_changed_files.txt

      - name: Parse apply id
        id: parse
        shell: bash
        run: |
          set -euo pipefail
          APPLY_ID="$(node scripts/sec002/parse-apply-id.mjs)"
          echo "apply_id=${APPLY_ID}" >> "$GITHUB_OUTPUT"
          echo "APPLY_ID=${APPLY_ID}" >> "$GITHUB_ENV"

      - name: Validate apply-map
        run: node scripts/sec002/validate-apply-map.mjs

      - name: Gate 01 — validate PR checklist
        run: node scripts/sec002/validate-pr-checklist.mjs

      - name: Gate 02 — validate changed files
        run: node scripts/sec002/validate-changed-files.mjs /tmp/sec002_changed_files.txt

      - name: Gate 03 — validate staging parity
        run: node scripts/sec002/validate-staging-parity.mjs

      - name: Gate 04 — validate go/no-go
        run: node scripts/sec002/validate-go-no-go.mjs --apply-id "${APPLY_ID}" --file ".github/sec002-go-no-go/${APPLY_ID}.md"

      - name: Gate 05 — validate comms log
        run: node scripts/sec002/validate-comms-log.mjs --apply-id "${APPLY_ID}" --file ".github/sec002-comms/${APPLY_ID}.md"

      - name: Gate 06 — validate DRI matrix
        run: node scripts/sec002/validate-dri-matrix.mjs --apply-id "${APPLY_ID}" --file ".github/sec002-dri/${APPLY_ID}.md"

      - name: Gate 07 — validate acceptance gates
        run: node scripts/sec002/validate-acceptance-gates.mjs --apply-id "${APPLY_ID}" --file ".github/sec002-acceptance/${APPLY_ID}.md"

      - name: Gate 08 — validate evidence archive
        run: node scripts/sec002/validate-evidence-archive.mjs --apply-id "${APPLY_ID}" --manifest ".github/sec002-evidence/${APPLY_ID}/manifest.json"

      - name: Gate 09 — sec002 consumers guard
        run: node scripts/sec002/check-consumers.mjs

      - name: Gate 10 — sec002 freeze guard
        run: node scripts/sec002/validate-freeze-guard.mjs --apply-id "${APPLY_ID}"

      - name: Gate 11 — sec-002 tests evidence
        run: node scripts/sec002/validate-tests-evidence.mjs --apply-id "${APPLY_ID}"

      - name: Summary
        if: success()
        run: |
          cat <<EOF >> "$GITHUB_STEP_SUMMARY"
          # sec002-pr-checklist

          - apply_id: ${APPLY_ID}
          - gates: 11/11 OK
          - apply_map_schema: v2026-07-12.2
          EOF
```

## 4. Contrato do parser `parse-apply-id.mjs`

O workflow acima pressupõe um utilitário determinístico, materializado em changeset próprio posterior:

```text
scripts/sec002/parse-apply-id.mjs
```

Contrato mínimo:

1. ler `PR_TITLE` e `PR_BODY` do ambiente;
2. extrair `apply_id` do título no formato `[SEC-002][apply:<id>]`;
3. extrair `sec002_apply_id: <id>` do corpo;
4. validar igualdade entre título e corpo;
5. validar existência do id no apply-map via `loadApplyMap()`;
6. imprimir somente o id em `stdout` quando OK;
7. imprimir `[sec002/parse-apply-id] FAIL - <motivo>` em `stderr` e sair `1` em falha.

Motivo: os gates 4–11 usam o mesmo `APPLY_ID`; reimplementar parsing em cada step aumentaria risco de divergência.

## 5. Invariantes W1–W11

| Regra | Invariante |
|---|---|
| W1 | workflow roda somente em PR cujo título contém `[SEC-002][apply:` |
| W2 | `permissions` limita a `contents: read` e `pull-requests: read` |
| W3 | `timeout-minutes` definido e `concurrency` cancela execução obsoleta |
| W4 | `validate-apply-map` roda antes de qualquer gate dependente do mapa |
| W5 | gates 1–11 aparecem exatamente na ordem de R44 §7 |
| W6 | `validate-dri-matrix` é gate 6, depois de comms e antes de acceptance |
| W7 | `check-consumers.mjs` é gate 9 e roda no mesmo job |
| W8 | nenhum step usa secrets, rede externa ou permissões de escrita |
| W9 | `APPLY_ID` é parseado uma vez e propagado via `$GITHUB_ENV` |
| W10 | todo path de artefato auditável usa o mesmo `${APPLY_ID}` |
| W11 | summary só é emitido em sucesso, com `gates: 11/11 OK` |
