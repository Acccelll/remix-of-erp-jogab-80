# PRO-012 · slice-03 — Ajustes propostos a partir da divergência

## Escopo
Ao concluir uma contagem cíclica, o sistema deriva a lista de **ajustes
propostos** por item com divergência ≠ 0, e permite marcar cada ajuste
como *aplicado*, *dispensado* ou *reaberto*. Persistência 100% local
(auditoria).

## Alterações
- `src/lib/estoque/contagens-ciclicas.ts`
  - Novo tipo `AjusteContagem` (`insumoId`, `tipo`, `quantidade`,
    `status`, `aplicadoEm`, `aplicadoPor`, `observacao`) e
    `StatusAjusteContagem`.
  - Campo opcional `ajustes?: AjusteContagem[]` em `ContagemCiclica`.
  - `gerarAjustesPropostos(contagem)` — deriva ajustes preservando o
    status prévio quando tipo/quantidade coincidem.
  - `marcarAjuste(contagemId, insumoId, patch)` — muda status e
    registra `aplicadoEm` automaticamente.
  - `STATUS_AJUSTE_LABEL` para exibição.
- `src/pages/suprimentos/ContagensCiclicas.tsx`
  - `salvarExecucao(true)` agora grava `ajustes` gerados.
  - Nova função `aplicarAjuste` chamando `marcarAjuste`.
  - Dialog de execução exibe seção **"Ajustes propostos"** quando a
    contagem está concluída, com botões *Aplicar / Dispensar / Reabrir*
    e nota sobre a RPC oficial ainda indisponível.

## Fora de escopo (registrado)
- **Emissão real do movimento** em `estoque_movimentacoes` /
  `estoque_saldos`: requer RPC dedicada `fn_estoque_ajuste` no backend.
  A UI já sinaliza essa pendência ao operador. Slice futura fará a
  ponte quando a RPC estiver disponível.
- Aprovação hierárquica antes da aplicação.
- Filtro por curva ABC no plano.

## Validação
- `bunx tsgo -p tsconfig.app.json` sem erros nos módulos alterados.
- `gerarAjustesPropostos` preserva status prévio (idempotente para o
  mesmo tipo/quantidade), evitando perder auditoria ao editar itens.
- Todos os fluxos anteriores (criar, iniciar, salvar parcial) intactos.
