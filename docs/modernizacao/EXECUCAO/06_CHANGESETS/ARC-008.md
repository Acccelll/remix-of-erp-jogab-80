# ARC-008 — Registro central de query keys

**Onda:** 3 · **Categoria:** Arquitetura · **Prioridade:** P2 · **Criticidade:** C2
**Relacionado:** ARC-003, TST-002

## Problema

As chaves do React Query eram strings ad-hoc espalhadas por páginas, hooks e componentes. Invalidações cruzadas dependiam de busca textual e memória do autor (Etapa 4, D9).

## Ação

1. Criado o registro canônico [`src/lib/query-keys.ts`](../../../../src/lib/query-keys.ts):
   - lista todos os prefixos de `queryKey` existentes;
   - expõe `queryKey(root, ...parts)` como fábrica para novos hooks;
   - expõe `isRegisteredQueryKeyRoot()` para validação.
2. Adicionado guardião automatizado [`src/lib/__tests__/query-keys.test.ts`](../../../../src/lib/__tests__/query-keys.test.ts):
   - exige registro ordenado e sem duplicatas;
   - falha se qualquer novo `queryKey: ["..."]` ou `queryKey("...")` usar prefixo não registrado.
3. Primeiros consumidores migrados para a fábrica central:
   - `src/hooks/financeiro/useObrasFinanceiro.ts`
   - `src/lib/financeiro-totvs/queries.ts`
   - `src/lib/financeiro-totvs/centros.ts`

## Critérios de aceite

- (a) Registro/fábrica central de query keys ✅
- (b) Cobertura automática dos prefixos já existentes ✅
- (c) Migração incremental por domínio sem alteração de comportamento ✅
- (d) Invalidações futuras impedidas de criar prefixos órfãos ✅

## Observação operacional

Literais legados permanecem válidos enquanto cada domínio é tocado por ARC-003/BIZ-002. O bloqueio efetivo é contra **novos prefixos não registrados**, eliminando crescimento do débito.
