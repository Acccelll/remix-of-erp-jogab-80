# PRO-026.slice-01 — Reconciliação Lean × CPM (regra pura)

**Onda:** 7 · **Achado:** PRO-026 · **Tipo:** NEW · **Escopo:** SEQUENCIAL (M3, M4)

## Problema

Não há reconciliação formal entre o plano Lean (pacotes de trabalho) e o
cronograma CPM. Itens do cronograma podem existir sem nenhum pacote que
os operacionalize, pacotes podem ficar órfãos (sem vínculo ao item), e
pacotes 100% concluídos não sinalizam que o item CPM correspondente
está pronto para ser atualizado. Hoje esse cruzamento é feito no olho.

## Alterações

`src/lib/planejamento/reconciliacao.ts` (novo, `@module-kind pure`):
- `reconciliarLeanCpm(itens, pacotes)` cruza `cronograma_itens` com
  `pacotes_trabalho` via `cronograma_item_id`.
- Devolve: `itens_sem_pacote`, `pacotes_orfaos`, `cobertura[]` com
  `total_pacotes`, `comprometidos`, `concluidos`, `completo_lean`, e
  a flag `divergente` (Lean 100% concluído × CPM ainda aberto).
- Sem I/O; consumidor injeta dados já filtrados por obra.

`src/lib/planejamento/__tests__/reconciliacao.test.ts` (novo):
- item sem pacote + pacote órfão contabilizados corretamente;
- agregação de comprometidos/concluídos por item;
- divergência quando pacotes 100% concluídos e CPM em andamento;
- não divergência quando CPM já concluído.

## Não escopo

- Não altera schema/RLS/repositórios.
- Não expõe UI (fica para `slice-02`).
- Não escreve de volta no cronograma (o gesto de "promover conclusão
  para o CPM" fica para slice posterior, se necessário).

## Validação

- `bunx vitest run src/lib/planejamento` → 4/4 verde.
- Regra pura; sem alteração de banco.
