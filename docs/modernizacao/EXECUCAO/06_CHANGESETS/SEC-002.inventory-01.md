# SEC-002.inventory-01 — Matriz de políticas RLS por tabela

**Onda:** 2 (bloqueada — dependente do fechamento do release train `SEC-001`)  
**Data:** 2026-07-12  
**Escopo:** primeiro entregável executável do `SEC-002.plan-01`. Define o **formato canônico** da matriz de inventário das políticas RLS do schema `public` e o **procedimento de coleta** que alimenta os lotes B–E. **Nenhuma migração é aplicada. Nenhum código de produção é alterado.**

## 1. Objetivo

Produzir, para cada tabela do schema `public`, uma linha auditável contendo:

1. políticas atuais (nome, comando, roles, `USING`, `WITH CHECK`);
2. classificação de risco (permissiva vs. restritiva vs. anônima);
3. **regra-alvo** desejada (quem pode ler/escrever e sob qual condição de negócio);
4. **helper de autorização** a ser usado (`current_is_gm`, `has_role`, `user_in_empresa`, `user_in_obra`, etc.);
5. **teste obrigatório** que valida a regra-alvo (nome do caso, tipo, dado sintético);
6. lote de execução (B/C/D/E) e dependências.

A matriz é o **único insumo aceito** para escrever qualquer migração de `SEC-002.*`. Migração sem linha correspondente na matriz é rejeitada no gate.

## 2. Fontes de verdade

- `supabase.read_query` sobre `pg_policies`, `pg_class`, `information_schema.role_table_grants`.
- Linter de segurança (`supabase.linter`) — 163 avisos atuais.
- `docs/modernizacao/` — mapa de domínios funcionais (obras, DP, financeiro, patrimônio, frota, registro).
- Memórias `funcionalidades/*` e `auth/hierarquia-e-permissoes` para regra de negócio por módulo.
- `SEC-001.k.spec-01` para contrato de RBAC server-sourced (`has_role`, `current_is_gm`).

## 3. Formato canônico da linha

Cada tabela ocupa uma linha em `SEC-002.inventory-02.csv` (a ser gerado no próximo passo) com o cabeçalho fixo:

```text
schema,table,cmd,policy_name,roles,using_expr,check_expr,classification,target_rule,helper,test_id,batch,depends_on,notes
```

Campos:

| Campo | Domínio | Observação |
|-------|---------|------------|
| `schema` | sempre `public` | outros schemas fora de escopo |
| `table` | nome exato | uma linha por política; tabela sem política gera linha com `policy_name = <none>` |
| `cmd` | `SELECT` \| `INSERT` \| `UPDATE` \| `DELETE` \| `ALL` | espelha `pg_policies.cmd` |
| `policy_name` | string | `<none>` quando não há política |
| `roles` | csv de roles | `{anon,authenticated,service_role,public}` |
| `using_expr` | SQL bruto | `null` se ausente |
| `check_expr` | SQL bruto | `null` se ausente |
| `classification` | `permissive-authenticated` \| `permissive-anon` \| `restrictive` \| `owner-scoped` \| `role-scoped` \| `empresa-scoped` \| `obra-scoped` \| `missing-rls` \| `missing-policy` | classificação inicial da política atual |
| `target_rule` | texto curto | regra de negócio-alvo em linguagem natural (ex.: "somente membros da empresa da obra podem `SELECT`") |
| `helper` | nome de função SQL | `public.current_is_gm()`, `public.has_role(...)`, `public.user_in_empresa(...)`, etc.; `<new>` se helper ainda não existe |
| `test_id` | id do teste | referência para `SEC-002.tests-01` (a criar) |
| `batch` | `B` \| `C` \| `D` \| `E` | lote de execução conforme `SEC-002.plan-01` §5 |
| `depends_on` | csv de ids | outras linhas/tabelas que precisam migrar antes |
| `notes` | texto livre | justificativas, riscos, exceções |

## 4. Procedimento de coleta (read-only)

Executar **em janela de leitura**, sem gravação:

1. `supabase.read_query`:
   ```sql
   select schemaname, tablename, policyname, cmd, roles, qual as using_expr, with_check as check_expr
   from pg_policies
   where schemaname = 'public'
   order by tablename, cmd, policyname;
   ```
2. `supabase.read_query`:
   ```sql
   select c.relname as table_name, c.relrowsecurity as rls_enabled, c.relforcerowsecurity as rls_forced
   from pg_class c
   join pg_namespace n on n.oid = c.relnamespace
   where n.nspname = 'public' and c.relkind = 'r'
   order by c.relname;
   ```
3. `supabase.read_query`:
   ```sql
   select table_name, grantee, privilege_type
   from information_schema.role_table_grants
   where table_schema = 'public'
     and grantee in ('anon','authenticated','service_role')
   order by table_name, grantee, privilege_type;
   ```
4. `supabase.linter` — anexar findings por tabela em coluna `notes`.
5. Consolidar em CSV UTF-8 salvo como `SEC-002.inventory-02.csv` (próximo changeset).

Nenhum passo grava no banco. Nenhum passo depende de `service_role`.

## 5. Classificação de risco (regras determinísticas)

Aplicar em ordem; primeira que casar vence:

1. `rls_enabled = false` → `missing-rls` (bloqueante).
2. Tabela sem qualquer política → `missing-policy` (bloqueante para escrita).
3. Política com `roles = {anon}` e `cmd` de escrita → `permissive-anon` (bloqueante).
4. Política com `using_expr = 'true'` e `roles ⊇ {authenticated}` → `permissive-authenticated`.
5. Expressão referencia `auth.uid() = <coluna_owner>` → `owner-scoped`.
6. Expressão usa `has_role(auth.uid(), ...)` ou `current_is_gm()` → `role-scoped`.
7. Expressão usa join/subselect por `empresa_id` → `empresa-scoped`.
8. Expressão usa join/subselect por `obra_id` → `obra-scoped`.
9. Qualquer outra → `restrictive` com `notes` detalhando.

## 6. Regra-alvo por domínio (guia de preenchimento)

| Domínio | Leitura | Escrita | Helper padrão |
|---------|---------|---------|---------------|
| Registry transversal (funções, NRs, tipos-doc) | `authenticated` | `current_is_gm() OR has_role('admin')` | `current_is_gm`, `has_role` |
| Obras / centros de custo | membros da empresa da obra | idem + `has_role('obras')` | `user_in_empresa`, `has_role` |
| DP (folha, provisões, horas) | `has_role('dp')` ou GM | idem, com `WITH CHECK` da mesma condição | `has_role`, `current_is_gm` |
| Financeiro (aprovação, despesas, formas pgto) | `has_role('compras')` ∪ `has_role('financeiro')` ∪ GM | segregação: solicitante ≠ aprovador | `has_role`, `current_is_gm` |
| Patrimônio / frota | membros da empresa dona | `has_role('patrimonio')` ou `has_role('frota')` | `user_in_empresa`, `has_role` |
| Cards/flows internos | proprietário do fluxo | proprietário + GM | `auth.uid()`, `current_is_gm` |

Toda linha da matriz deve nomear explicitamente **quem** (role/empresa/obra/owner) e **o quê** (leitura, escrita, ambos). Nunca `USING (true)` fora de tabelas de referência realmente públicas — e mesmo essas devem ser marcadas com `notes = "public reference — reviewed"`.

## 7. Invariantes do inventário

I1. Toda linha aponta um `helper` existente ou marcado `<new>` com issue rastreável.  
I2. Toda linha aponta um `test_id` — política sem teste não migra.  
I3. Toda tabela do schema `public` aparece pelo menos uma vez, mesmo que como `missing-policy`.  
I4. `service_role` nunca é restringido por RLS — apenas por `GRANT`.  
I5. `anon` só aparece em tabelas cuja regra-alvo é explicitamente "leitura pública" e assinadas em `notes`.  
I6. Nenhuma linha propõe remover política sem uma substituta na mesma migração (transição atômica).
