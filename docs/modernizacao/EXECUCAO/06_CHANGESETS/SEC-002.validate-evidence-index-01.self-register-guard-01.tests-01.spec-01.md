## 1. Objetivo canônico

R73 define o patch do validador, mas ainda falta uma suíte independente que prove, em CI, que:

1. o estado canônico pós-R71 permanece verde;
2. manifest físico órfão falha com `E_EVIDX_S1`;
3. `apply_id` duplicado falha com `E_EVIDX_S2` ou com o `E_EVIDX_E3` pré-existente;
4. diretório sem `manifest.json` é ignorado;
5. falha E1–E8 anterior aborta antes de S1–S6.

A suíte deve validar comportamento, não apenas presença textual do bloco.

## 4. Estratégia de fixtures temporárias

O runner deve:

1. criar `tmp/sec002-validate-evidence-index-self-register-guard/<case>/` do zero;
2. copiar o `INDEX.md` canônico para `<case>/.github/sec002-evidence/INDEX.md`;
3. copiar os manifests canônicos necessários para `<case>/.github/sec002-evidence/<apply-id>/manifest.json`;
4. criar os changesets docs referenciados como arquivos vazios controlados **somente dentro do fixture**, quando o validador aceitar raiz alternativa;
5. executar o validador apontando para o `INDEX.md` do fixture;
6. apagar o diretório do caso ao final, também em falha.

Se o validador não aceitar raiz alternativa em R75, a materialização deve usar `cwd=<case>` ao invocar o processo. É proibido escrever em `.github/sec002-evidence/**` real.

## 5. Casos obrigatórios T1–T5

| Teste | Fixture | Comando | Oráculo |
|---|---|---|---|
| T1 | cópia fiel do estado canônico pós-R71 (16 linhas + 16 manifests) | `node scripts/sec002/validate-evidence-index.mjs --file .github/sec002-evidence/INDEX.md` dentro do fixture | exit `0`, contém `[sec002/validate-evidence-index] OK` |
| T2 | T1 + `.github/sec002-evidence/nova-evid/manifest.json`, sem linha no índice | mesmo comando | exit `1`, contém `E_EVIDX_S1` e `apply_id=nova-evid` |
| T3 | T1 + duplicação da linha 16 no índice | mesmo comando | exit `1`, contém `E_EVIDX_S2 apply_id=evidence-index-evidence-validator-bump-01 occurrences=2` **ou** `E_EVIDX_E3` |
| T4 | T1 + `.github/sec002-evidence/tmp/` sem `manifest.json` | mesmo comando | exit `0`, contém `OK`, não contém `E_EVIDX_S1` |
| T5 | T1 + linha extra apontando para manifest inexistente | mesmo comando | exit `1`, contém `E_EVIDX_E4`, não contém `E_EVIDX_S1`, não contém `E_EVIDX_S2` |

T5 prova S5: S1–S6 não rodam quando E1–E8 já falharam.
