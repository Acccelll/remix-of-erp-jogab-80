# PRO-016 · slice-01 — Workflow de aprovação de medição

**Onda:** 07 · **Prioridade:** P2 · **Categoria:** Produto · **Módulo:** M3 (Obra) / M8 (Financeiro)

## Problema

Antes deste slice, o botão único "Aprovar" na aba de Medições apenas
setava `status = 'aprovada'` e `data_aprovacao` — sem registrar quem
aprovou, sem estado intermediário de solicitação e sem caminho de
rejeição. O enum `medicao_status` já previa `enviada`/`aprovada`/
`rejeitada`, mas o fluxo não era exercitado.

Aceite (Etapa 5.5): _"estados de medição com aprovação registrada
(quem/quando) antes do faturamento."_

## Alterações

**Banco**
- Migration adiciona a `public.medicoes`:
  `aprovada_por text`, `aprovada_em timestamptz`,
  `enviada_por text`, `enviada_em timestamptz`,
  `rejeitada_por text`, `rejeitada_em timestamptz`,
  `rejeicao_motivo text`.

**Repositório (`src/lib/repositories/medicoes.ts`)**
- `enviarParaAprovacao(id, login)` — `rascunho|em_revisao|rejeitada → enviada`.
- `aprovar(id, login)` — `enviada → aprovada`, grava `aprovada_por/em` e
  `data_aprovacao` (compat com relatórios existentes).
- `rejeitar(id, login, motivo?)` — `enviada → rejeitada`, grava motivo.
- `listByObra` passa a retornar os novos campos de auditoria.

**UI (`src/components/obra-detalhe/MedicoesTab.tsx`)**
- Usa `useAuth().currentPlayer.login` como responsável do evento.
- Botão único substituído por transições contextuais:
  - `rascunho | em_revisao | rejeitada` → "Enviar para aprovação".
  - `enviada` → "Aprovar" + "Rejeitar" (motivo por prompt).
  - `aprovada | faturada` → mantém "Boletim".
- Badge de status agora mostra `por <login> · dd/MM/yy HH:mm` quando
  aprovada; motivo aparece em vermelho quando rejeitada.

## Escopo consciente

- Aprovação continua permitida a qualquer perfil com `canEdit` sobre a
  obra — segregação de função (só fiscalização aprova) fica para slice
  futuro (`PRO-016.slice-02`) junto com trilha em `historico_medicao`.
- Fluxo por notificações (`enviada → responsável fiscalização`) reusará
  o catálogo de `PRO-030` em slice futuro.

## Validação

- `bunx tsgo --noEmit` → limpo.
- Fluxo esperado: criar medição → botão "Enviar para aprovação" →
  status vira `enviada` com `enviada_por` gravado → aprovador vê
  "Aprovar"/"Rejeitar" → aprovada exibe carimbo `por <login>` no badge.
