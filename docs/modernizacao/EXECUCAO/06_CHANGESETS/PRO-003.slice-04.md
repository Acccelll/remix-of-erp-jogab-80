# PRO-003.slice-04 — Backend do fechamento de competência DP

**Onda:** 07 · **Achado:** PRO-003 · **Slice:** 04/n

## Entrega
- Nova tabela `public.dp_fechamento_competencia` com constraint de formato
  `YYYY-MM` e índice único parcial garantindo **um fechamento ativo por
  competência** (`WHERE reaberto_em IS NULL`).
- RLS habilitado: leitura livre a autenticados; mutações restritas a GM
  (`public.current_is_gm()`).
- RPCs `SECURITY DEFINER`:
  - `dp_fechar_competencia(p_competencia, p_fechado_por, p_motivo)`
  - `dp_reabrir_competencia(p_competencia, p_reaberto_por, p_motivo_reabertura)`
  - Ambas validam entrada, checam trava e gravam auditoria em `audit_logs`.
- Grants: `EXECUTE` a `authenticated`; permissão real controlada dentro da função.

## Regras respeitadas
- Estrutura CREATE → GRANT → ALTER → POLICY conforme padrão do projeto.
- Auditoria automática usando a tabela existente `public.audit_logs`.
- Warnings do linter na resposta são preexistentes; as duas policies novas
  seguem os padrões (SELECT `USING (true)` para leitura autenticada; mutações
  guarded por `current_is_gm()`).

## Não escopo (próximo slice)
- Hook cliente `useDpFechamentoCompetenciaRemoto` (RPC + cache TanStack)
  substituindo a persistência local somente quando o usuário for GM ou
  quando houver sessão autenticada. slice-05 fará o merge local↔remoto.
- Bloqueio server-side de inserts/updates em `dp_holerite` / `horas_extras`
  em competência fechada via trigger (slice-06).

## Validação
- Migração aplicada com sucesso.
- Nenhum warning novo atribuível a esta migração (linter pré-existente).
