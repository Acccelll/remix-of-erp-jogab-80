# OPS-002.a — Error tracking (Sentry) instalado e inicializado

**Onda:** 0 · **Categoria:** Observabilidade · **Prioridade:** P1 · **Criticidade:** C1
**Relacionado:** SEC-003, OPS-001.a, OPS-003 (logs estruturados, Onda futura)
**Waiver:** [W-001](../00_EXECUTIVO/06_WAIVERS.md) — `.a` (código, este changeset) fecha em M1; `.b` (criar projeto Sentry, provisionar `VITE_SENTRY_DSN`, validar evento) migra para Onda 7/M8.

## Problema

O helper `src/lib/sentry.ts` existia (herdado da H2.2) mas `@sentry/react` **nunca havia sido instalado** — o import estava suprimido com `@ts-expect-error` e `initSentry()` não era chamado no bootstrap. Na prática, error tracking estava desligado.

## Ação

1. Instalado `@sentry/react@10.65.0`.
2. Removido `@ts-expect-error` do `src/lib/sentry.ts` (dependência agora real).
3. `src/main.tsx` chama `initSentry()` **antes** do `createRoot(...).render()`.
4. Contrato de ativação preservado do helper original:
   - Sem `VITE_SENTRY_DSN`, `initSentry()` é NO-OP total — nenhum request sai.
   - `beforeSend` já filtra eventos disparados dentro do iframe de preview do Lovable, evitando ruído.
   - Sample rates conservadores (`traces 5% em prod, 0% em dev`, replay off).
5. `tsc --noEmit` limpo após a mudança.

## Como ativar (quando houver projeto Sentry)

1. Criar projeto no Sentry (plataforma **React**).
2. Copiar o DSN público.
3. Adicionar a variável **`VITE_SENTRY_DSN`** no build da app (Lovable → Settings → Environment ou `.env` local). Opcionalmente `VITE_APP_RELEASE` para atrelar erros ao commit.
4. Redeploy — o `initSentry()` detecta o DSN e o SDK passa a capturar exceptions e traces.

Nada mais precisa ser mexido no código.

## Critérios de aceite

- (a) `@sentry/react` presente em `dependencies` ✅
- (b) `initSentry()` chamado no bootstrap ✅
- (c) NO-OP validado sem DSN (build/typecheck limpos, nenhum request de rede) ✅
- (d) Documentação de ativação neste changeset ✅
- (e) Evento de teste chegando no dashboard Sentry ⏳ **pendente da criação do projeto e do DSN**
