# PRO-007.slice-02 — Mapper NCState ↔ nao_conformidades

**Onda:** 07 · `PRO-007`
**Escopo desta fatia:** apenas o adaptador puro entre o FSM (`slice-01`) e a linha persistida. Sem I/O, sem UI, sem migração — a coluna `aguardando_reinspecao` no banco vem em migration separada (slice-03), e enquanto isso o flag trafega em memória.

## Problema
O `NCState` do workflow tem cinco status (incluindo `aguardando_reinspecao`), mas `public.nao_conformidades.status` só aceita quatro. Sem um adaptador único, cada consumidor teria que reinventar o mapeamento — e o campo `aguardando_reinspecao` cairia no chão.

## Entrega
1. **`src/lib/inspecoes/nc-mapper.ts`** (`@module-kind pure`)
   - `NCStatusPersistido` fixado no legado (`aberta | em_tratativa | resolvida | cancelada`).
   - `NCRow` com colunas-alvo (`status`, `responsavel_id`, `prazo`, `tratativa`, `reinspecao_resultado`, `reinspecionada_em`, `encerrada_em`, `aguardando_reinspecao`).
   - `toRow(state)`: `aguardando_reinspecao` → `status="em_tratativa"` + flag `true`.
   - `fromRow(row)`: reidrata para `aguardando_reinspecao` quando a flag chega ativa; linhas legadas continuam como `em_tratativa`.
   - `diffRow(before, after)`: patch mínimo para `UPDATE`.
2. **`__tests__/nc-mapper.test.ts`** — 5 casos (mapeamento com flag, reidratação, compatibilidade legada, roundtrip, diff mínimo).

## Validação
- `bunx vitest run src/lib/inspecoes/__tests__/nc-mapper.test.ts src/lib/inspecoes/__tests__/nc-workflow.test.ts` → **12/12 verdes**.
- `bunx tsgo --noEmit` limpo.

## Fora de escopo
- **slice-03:** migration adicionando `responsavel_id / prazo / tratativa / reinspecao_resultado / reinspecionada_em / encerrada_em / aguardando_reinspecao` em `nao_conformidades` + GRANTs + policies.
- **slice-04:** repositório usando `toRow / fromRow / diffRow`.
- **slice-05:** UI (`NaoConformidades.tsx`) consumindo `transition`.
- **slice-06:** gatilho de notificação via `PRO-030`.
