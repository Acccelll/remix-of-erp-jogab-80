## 1. Racional

R63 bumpou o apply-map para `v2026-07-12.4`, registrando `validate-evidence-index.mjs` como consumidor auditado (categoria `evidence`) e protegendo `.github/sec002-evidence/INDEX.md`. R61 materializou o validador. Sem esta atualização controlada do workflow:

- o `sec002-pr-checklist` continuaria congelado em `v2026-07-12.3` (W12–W14 de R56/R57);
- `validate-evidence-index.mjs` seria auditável pelo `sec002-consumers-guard` mas não seria efetivamente executado a cada PR de apply;
- divergências entre `INDEX.md` e evidências físicas não bloqueariam merge, contrariando E1–E8 de R58.

## 2. Delta canônico do workflow

Aplicar exclusivamente estes deltas sobre R57 §3:

### 2.1 Anotação de versão

Substituir o comentário de topo (linhas 1–3 do arquivo) por:

```yaml
# sec002-pr-checklist
# apply-map: v2026-07-12.4
# consumers: parse-apply-id (parser) + 11 gates + validate-evidence-index (evidence)
```

### 2.2 Passo `validate-apply-map`

Inalterado. Continua sendo o gate 1 lógico e passa a rodar com M17–M19 automaticamente por consumir o binário de R63.

### 2.3 Novo gate `validate-evidence-index`

Adicionar como **último passo** do job, imediatamente após `sec002-freeze-guard`/`sec002-consumers-guard` (mantendo a ordem canônica de R50 preservada até esse ponto):

```yaml
- name: validate-evidence-index  # consumer id="validate-evidence-index" category="evidence"
  run: node scripts/sec002/validate-evidence-index.mjs
```

Nenhuma flag, nenhum `working-directory`, nenhum `env` novo. O binário lê `APPLY_ID` do `$GITHUB_ENV` (emitido por `parse-apply-id`) e o apply-map `v2026-07-12.4` pelo loader compartilhado.

### 2.4 Ordem final

**11 gates operacionais de R50 permanecem literais e nessa ordem.** O novo passo é gate auditável adicional (não operacional), posicionado após o último gate de R50. Contagem final: `1 pré-gate + 11 gates operacionais + 1 gate de evidência`.

## 3. Novas invariantes (W15–W17)

- **W15.** O comentário de topo declara `apply-map: v2026-07-12.4`; qualquer divergência com `SCHEMA_VERSION` do loader é violação.
- **W16.** `validate-evidence-index` é o **último** passo do job, executa exatamente `node scripts/sec002/validate-evidence-index.mjs` e não recebe flags.
- **W17.** Nenhum gate de R50 é reordenado, removido ou renomeado; a inserção é exclusivamente aditiva no final.

W1–W14 permanecem inalteradas.

- Comentário de topo divergente de `v2026-07-12.4`;
- `validate-evidence-index` inserido fora da última posição, com flags, ou com caminho diferente;
- Qualquer passo dos 11 gates de R50 renomeado, removido, reordenado ou com `run:` alterado;
- Introdução de `secrets`, `permissions: write-*` ou chamadas de rede externas;
- Alteração em `src/**`, `supabase/functions/**` ou `supabase/migrations/**`;
- Ausência de manifesto de evidência em `.github/sec002-evidence/pr-checklist-workflow-evidence-validator-bump-01/`.
