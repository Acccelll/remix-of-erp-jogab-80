# PRO-007.slice-03 — Migration do workflow de Não Conformidades

**Onda:** 07 · `PRO-007`  
**Achado-base:** PRO-007 — "NC sem workflow ativo (sem responsável/prazo/reinspeção/notificação)".  
**Dependências satisfeitas:** `PRO-007.slice-01` (FSM) e `PRO-007.slice-02` (mapper).  
**Escopo desta fatia:** schema e RLS de `public.nao_conformidades`. Sem UI, sem repositório, sem gatilho dedicado de notificação.

## Problema

O workflow puro já existia, mas a base ainda não garantia colunas para persistir responsável, prazo, tratativa, resultado de reinspeção, datas de reinspeção/encerramento e o estado intermediário `aguardando_reinspecao`. Além disso, o ambiente atual não tinha `public.nao_conformidades` aplicada, então a primeira tentativa de `ALTER TABLE` falhou com:

```text
ERROR: 42P01: relation "public.nao_conformidades" does not exist
```

## Entrega

1. **Migration `20260714123845_7a6231b4-f403-4e19-afe2-1ff5389f3053.sql`**
   - Bootstrap idempotente de `public.nao_conformidades` quando a tabela ainda não existe.
   - `GRANT SELECT, INSERT, UPDATE, DELETE` para `authenticated` e `GRANT ALL` para `service_role` no mesmo bloco da criação.
   - RLS habilitado com policies para leitura/criação/edição/exclusão alinhadas a GM, criador, responsável e vínculo com obra.
   - Colunas novas do workflow:
     - `responsavel_id`
     - `prazo`
     - `tratativa`
     - `reinspecao_resultado`
     - `reinspecionada_em`
     - `encerrada_em`
     - `aguardando_reinspecao`
   - Constraints:
     - `status` limitado a `aberta | em_tratativa | resolvida | cancelada`.
     - `reinspecao_resultado` limitado a `aprovada | reprovada` quando preenchido.
     - `aguardando_reinspecao=true` permitido apenas com `status='em_tratativa'`.
   - Índices para status, obra, inspeção, card, responsável, prazo de NCs abertas e fila de reinspeção.
   - Triggers idempotentes para `updated_at`, geração de código e carimbo de resolução/encerramento.

2. **Compatibilidade legada**
   - Quando existirem colunas 5W2H antigas, a migration preserva o contrato esperado pelo mapper.
   - A sincronização operacional com `quem/quando_planejado/como` fica para o repositório/UI da próxima fatia.

3. **`src/lib/inspecoes/nc-mapper.ts`**
   - Comentário atualizado para indicar que `aguardando_reinspecao` já foi materializado no schema por este slice.

## Validação

- Migration aplicada com sucesso após ajuste para bootstrap idempotente.
- Consulta de schema confirmou as colunas novas em `public.nao_conformidades`:
  - `responsavel_id uuid`
  - `prazo timestamptz`
  - `tratativa text`
  - `reinspecao_resultado text`
  - `reinspecionada_em timestamptz`
  - `encerrada_em timestamptz`
  - `aguardando_reinspecao boolean NOT NULL DEFAULT false`
- Linter retornou avisos pré-existentes globais do projeto; nenhum bloqueio específico desta fatia foi identificado no contrato criado.
