# SEC-006.slice-01 — Helper `withDeadline` para deadlines explícitos

**Onda:** 7 · **Achado:** SEC-006 · **Tipo:** STD · **Escopo:** LOTE
(Transversal) · **Dependência:** QC-003 (satisfeita).

## Problema

`fetchWithRetry` já tratava timeout para `fetch` de terceiros, mas
chamadas Supabase (`from().select()`, RPCs) e Promises arbitrárias
(reads de repos, uploads de storage, geração de PDF client-side) não
tinham deadline explícito. Um endpoint lento travava a UI
indefinidamente — usuário via spinner eterno.

## Alterações

`src/lib/http/withDeadline.ts` (novo)
- Função pura `withDeadline<T>(promise, ms, labelOrOpts)` que envelopa
  qualquer Promise e rejeita com `DeadlineExceededError` se `ms`
  estourar antes da conclusão. Logger estruturado registra
  `deadline_exceeded` com `label` e `timeoutMs`.
- Classe `DeadlineExceededError` (nome + code `DEADLINE_EXCEEDED`)
  para o consumidor diferenciar do resto via `isDeadlineExceeded`.
- `ms <= 0` ou não-finito desliga o wrapper (útil em testes/dev).
- `onTimeout` opcional para cleanup local (cancelar UI, invalidar
  cache, etc.). **Não** cancela a Promise subjacente — JS puro não
  suporta; wrapper garante apenas que o chamador destrave.

`src/lib/http/__tests__/withDeadline.test.ts` (novo)
- 6 casos: resolve rápido, deadline estoura, rejeição precoce
  preservada, `onTimeout` invocado, `ms<=0` no-op, guard de tipo.

## Não escopo

- Não migra consumidores existentes — helper disponível; adoção
  segue conforme achados específicos (repositórios pesados vêm em
  próximas slices se surgir sinal).
- Não substitui `fetchWithRetry` — este continua ideal para
  transporte HTTP com retry; `withDeadline` cobre o gap para o
  restante das Promises.
- Não integra com AbortController do Supabase JS (v2 ainda não
  expõe signal em todas as chamadas de forma estável).

## Validação

- `bunx tsgo --noEmit` limpo.
- `bunx vitest run src/lib/http/__tests__/withDeadline.test.ts` → 6/6 verde.

## Estado

**SEC-006 aberto para adoção** — helper e padrão definidos. Fechamento
formal do Achado exige uso em pelo menos os 3 fluxos com maior tempo
médio observado (a definir após instrumentação OPS-004).
