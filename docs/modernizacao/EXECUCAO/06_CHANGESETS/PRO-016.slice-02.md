# PRO-016 · slice-02 — Notificação de medições aguardando aprovação

**Onda:** 07 · **Achado:** PRO-016 · **Depende de:** slice-01 (workflow enviar/aprovar/rejeitar) e PRO-030.slice-01 (framework de preferências).

## Contexto
O slice-01 introduziu o workflow `enviada → aprovada|rejeitada` com carimbos de auditoria, mas não avisava o responsável de que havia medição parada no seu balde. Este slice fecha a lacuna sinalizada em "próximo" do slice-01, reaproveitando o catálogo de PRO-030.

## Entrega
- `src/hooks/useMedicoesAguardandoAprovacao.ts` (novo): consulta `medicoes` filtradas por `status = 'enviada'`, projeta `{id, obraId, numero, valor, enviadaEm, enviadaPor, diasEsperando}`, refresh a cada 60s. `enabled=false` retorna `[]` sem tocar no backend.
- `src/hooks/useNotifPreferencias.ts`: nova categoria `medicao_aguardando_aprovacao`.
- `src/components/layout/NotificationBell.tsx`:
  - Consome `useMedicoesAguardandoAprovacao(canAprovarMedicao && isVisivel("medicao_aguardando_aprovacao"))` — `canAprovarMedicao = hasAccess("obras_div","editar")`.
  - Nova seção com ícone `ClipboardCheck` após "Snapshot TOTVS", listando até 15 medições com `Medição N · Obra`, badge de idade (`hoje` / `Nd`, cor escalonada em 3/7 dias).
  - Item leva a `/obras/:id`.
  - Contribui para `totalBadge` global.

## Não escopo
- Segregação de função (só fiscalização aprova) — mantém decisão do slice-01, aguarda `PRO-016.slice-03`.
- Trilha em `historico_medicao` — idem.
- Filtro por obra do usuário (hoje mostra todas as pendentes visíveis ao perfil).

## Validação
- `bunx tsgo --noEmit` limpo.
- Fluxo manual: enviar medição para aprovação → sino recebe `+1` para usuários com `obras_div:editar`; ocultar a categoria nas Preferências remove a seção e desconta do badge.
