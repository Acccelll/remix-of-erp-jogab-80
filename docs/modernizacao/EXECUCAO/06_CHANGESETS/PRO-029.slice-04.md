# PRO-029 · slice-04 — Embed opcional de miniaturas e assinatura no PDF

**Onda:** 07 · **Prioridade:** P2 · **Marco:** M5 · **Depende de:** `PRO-029.slice-03`

## Contexto

O índice textual de evidências (slice-03) resolvia rastreabilidade, mas o
auditor ainda precisava abrir o bucket para ver cada foto. Para arquivamento
"stand-alone" o PDF deveria carregar miniaturas e a assinatura embutidas —
sem, contudo, acoplar o módulo puro de export a `supabase.storage`.

## Entrega

- **`src/lib/inspecoes/export-pdf.ts`**
  - Novo tipo `CarregarImagemPdf = (path) => Promise<string | null>` e campo
    opcional `carregarImagem` em `ExportOpts`.
  - `exportInspecaoToPDF` agora é `async`.
  - Nova seção "Miniaturas" (120×90 pt, grade auto-quebra) renderizada logo
    após o índice de fotos quando `carregarImagem` está presente. Falha por
    foto é silenciada — as demais continuam.
  - Assinatura: se `assinatura_path` e loader existirem, embute imagem acima
    da linha de assinatura (fallback textual permanece intacto).
  - Detecção de formato via regex no data URL (`png|jpe?g|webp`) para escolher
    o mime aceito por `jsPDF.addImage`.

- **`src/pages/InspecaoCaptura.tsx`**
  - Botão "PDF" agora `async`, injeta `carregarImagem` que baixa do bucket
    `inspecoes-fotos` via `supabase.storage.download` e converte para data URL
    com `FileReader`. Sem loader = comportamento antigo (só índice textual).

## Impacto

- Sem alteração de schema, RLS, hook offline ou tipos de dados.
- Chamadores existentes que não passam `carregarImagem` continuam idênticos —
  apenas precisam de `await`/`.then` por causa da assinatura assíncrona.
- Custo de rede proporcional ao número de fotos; suportado apenas online.

## Validação

- `bunx tsgo --noEmit` limpo.
- Loader isola erros por arquivo; PDF nunca aborta por falha de download.
