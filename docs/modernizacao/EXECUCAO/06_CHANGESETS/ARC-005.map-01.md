## 4. Dependências transversais

- **Supabase direto no provider:** `import { supabase } from "@/integrations/supabase/client"` — a maior parte das escritas passa pelos hooks; provider ainda ancora chamadas de bootstrap (login/logout) e a orquestração de `mobilizacoes`.
- **PHP legado:** `import { api } from "@/lib/api"` — resíduo pré-Onda 2 (autenticação e alguns CRUDs de colaborador/obra ainda batem no PHP; convivência regida por D-1).
- **Refs estáveis:** `currentPlayerRef`, `colaboradoresRef`, `funcoesRef` — usadas para expor getters memoizados (`getCurrentPlayer`, `getColaboradoresStable`, `getFuncoesStable`) e alimentar `useMobilizacoes` sem re-render em cascata.
- **Toast/telemetria:** `sonner`, `swallow`.
- **Domínio:** `isSpecialStatus` (cards), `PageKey`, `NivelAcesso` (RBAC estático).

## 5. Consumidores (agregados)

- **90 arquivos** em `src/**` chamam `useApp()` — páginas de todas as áreas (`pages/rh`, `pages/dp`, `pages/financeiro`, `pages/suprimentos`, `pages/crm`, `pages/planejamento`, `pages/admin`, `pages/inspecoes`, dashboards e componentes de layout).
- Nenhum componente consome hooks internos (`useObrasState`, etc.) diretamente — o provider é o único ponto de entrada.
- Componentes de card/board e diálogos de mobilização são os maiores consumidores por área de superfície acionada (múltiplas chaves da interface em uma mesma tela).

## 6. Riscos identificados para ARC-005

1. **Contexto único e pesado** — 65 chaves, ~2.8k LOC de estado agregado, todos os consumidores re-renderizam ao mudar qualquer domínio. Alvo direto de PERF-001 (particionar contexto por domínio ou expor seletores).
2. **`useMobilizacoes` é monólito (800 LOC)** — concentra regras cross-domínio (colaborador × patrimônio × veículo × obra × responsabilidades). Precisa fatiar antes de qualquer refator de contexto.
3. **Fontes mistas (Supabase + PHP)** — provider ainda toca `@/lib/api`. Cutover de Onda 2 (D-1) precisa concluir para eliminar o duplo caminho antes de dividir o contexto.
4. **90 consumidores** — qualquer mudança de forma da API pública precisa vir com _codemod_ (candidato a DS-016) ou wrapper de compatibilidade temporário.
5. **Refs manuais** — o padrão `xxxRef` mostra que o próprio provider já sofre com invalidations; particionamento deve preservar a semântica dos getters estáveis.

## 7. O que este artefato NÃO faz

- Não altera código de produção.
- Não propõe o novo desenho do contexto (isso é entregável da própria ARC-005 quando a Onda 6 destravar).
- Não conta LOC de componentes consumidores — só do provider e dos hooks agregados.
