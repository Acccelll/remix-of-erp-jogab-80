**Escopo:** especificar, como contrato executável, o reforço do validador `scripts/sec002/validate-evidence-index.mjs` com um guarda determinístico — `self-register-guard` — que impede o cenário em que um manifest físico existe em `.github/sec002-evidence/<apply-id>/manifest.json` mas **não está indexado** pelo `INDEX.md`. Fecha executavelmente a invariante E5 de R58 e institucionaliza o padrão exercido em R70/R71. **Nenhum arquivo de produção é alterado nesta etapa.** Materialização em `SEC-002.validate-evidence-index-01.self-register-guard-01.materialize-01` (R73).

## 1. Motivação canônica

R58/E5 declara: "todo manifest existente em `.github/sec002-evidence/**` está indexado". R61 implementou E4 (todo item indexado tem manifest existente) e E5 apenas como bijeção parcial. R70/R71 mostraram que, sem gate simétrico, um bump que cria manifest novo pode "esquecer" a linha de indexação até o apply seguinte — janela na qual E5 fica violada e o freeze/checklist não bloqueiam. Este spec elimina a janela.

## 2. Invariantes específicas (S1–S6)

| Regra | Descrição executável |
|---|---|
| S1 | O validador enumera todos os `apply-id` presentes como diretório em `.github/sec002-evidence/*/manifest.json` |
| S2 | Para cada `apply-id` enumerado em S1, existe **exatamente uma** linha em `INDEX.md` cujo campo `apply_id` (coluna 2) é igual |
| S3 | Divergência de S2 emite `E_EVIDX_S1` com o `apply-id` faltante e o caminho do manifest órfão |
| S4 | Diretórios em `.github/sec002-evidence/` que **não** contêm `manifest.json` são ignorados (não são apply-id válidos) e não geram erro |
| S5 | O guarda roda **após** E1–E8 já validados; falha em qualquer um de E1–E8 aborta antes de S1 (short-circuit) |
| S6 | Códigos de erro exclusivos: `E_EVIDX_S1` (manifest órfão), `E_EVIDX_S2` (mais de uma linha para o mesmo `apply-id` — reforço adicional a E3) |

E1–E8 permanecem integralmente válidos; S1–S6 estendem sem revogar.

## 3. Contrato de execução

Assinatura preservada: `node scripts/sec002/validate-evidence-index.mjs` (sem flags novas).

Fluxo canônico:

1. Carrega apply-map via `loadApplyMap()` (herdado de R61).
2. Lê `.github/sec002-evidence/INDEX.md`.
3. Executa E1–E8 na ordem de R60/R61. Aborta na primeira falha.
4. Enumera diretórios `.github/sec002-evidence/*/` que contenham `manifest.json` legível.
5. Constrói o conjunto `INDEXED = { apply_id da coluna 2 de cada linha 11..N }`.
6. Para cada `apply-id ∈ FILES \ INDEXED`, emite `E_EVIDX_S1` (código de saída ≠ 0).
7. Para cada `apply-id ∈ INDEXED` que aparece em mais de uma linha, emite `E_EVIDX_S2`.
8. Em sucesso, imprime `[sec002/validate-evidence-index] OK` (mensagem inalterada — compatibilidade com gate do workflow).

Formato de erro (uma linha por ocorrência):

```
E_EVIDX_S1 apply_id=<id> manifest=.github/sec002-evidence/<id>/manifest.json hint="adicione linha no INDEX.md apontando para este manifest"
E_EVIDX_S2 apply_id=<id> occurrences=<n> hint="cada apply_id deve aparecer exatamente uma vez em INDEX.md"
```
