# PRO-007.slice-05 — UI de NCs consumindo o workflow FSM

**Onda:** 07 · **Achado:** PRO-007 · **Slice:** 05 (UI/FSM)

## Objetivo
Substituir o `Select` livre de `status` da tela `NaoConformidades` por ações formais do workflow (`nc-workflow` + `naoConformidadesRepo.applyTransition`), garantindo que toda mudança de estado passe pela FSM.

## Entregas
1. `src/pages/NaoConformidades.tsx`
   - `NCRow` estendido com colunas do workflow (`responsavel_id`, `prazo`, `tratativa`, `reinspecao_resultado`, `reinspecionada_em`, `encerrada_em`, `aguardando_reinspecao`).
   - Query `ncs` seleciona as novas colunas.
   - `fsm = ncWorkflowFromRow(editing)` calcula o estado real (incluindo `aguardando_reinspecao`).
   - Novo painel **Fluxo de tratativa** dentro do dialog com botões contextualizados:
     - `Atribuir responsável` (usa Quem + Quando → `atribuir`)
     - `Registrar tratativa` (usa Como/Ação corretiva → `registrar_tratativa`)
     - `Solicitar reinspeção` (`solicitar_reinspecao`)
     - `Aprovar reinspeção` / `Reprovar reinspeção` (`reinspecionar`)
     - `Cancelar NC` (`cancelar`, com motivo via prompt)
   - `runTransition()` traduz `NCTransitionError` para toasts em pt-BR e recarrega a linha após transições não-finais; fecha o dialog em estados finais.
   - `Fechar NC` legado (fluxo direto sem reinspeção) mantido por compatibilidade.
2. `src/lib/status.ts`: `STATUS_NC_LABEL` e `STATUS_NC_COLOR` ganham entrada para `aguardando_reinspecao`.

## Compatibilidade
- Nenhuma alteração de schema. Persistência continua via `enrichLegacyPatch` / `mirrorWorkflowPatch` do repositório (slice-04).
- `salvar()` legado permanece para edições dos campos 5W2H e "Fechar NC" direto (bypass de reinspeção).
