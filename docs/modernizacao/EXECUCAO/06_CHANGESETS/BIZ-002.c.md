# BIZ-002.c — Extração de puros e reclassificação de orquestradores em `src/lib`

**Onda:** 3
**Achado:** BIZ-002 (Lote C)
**Status:** concluído

## Objetivo
Avançar a convenção bimodal introduzida em BIZ-002.a/b, extraindo lógica pura embutida em módulos `io` e marcando corretamente como `orchestration` os que combinam múltiplas fontes de I/O + regras de domínio.

## Mudanças

### Novos módulos puros (`@module-kind pure`)
- `src/lib/obras/payload.ts` — `buildObraPayload(obra)` extraído de `src/lib/obras/sync.ts`.
- `src/lib/faturamento/resolver-obra.ts` — `criarResolverObraNfse(mapaCentros, mapaObras)` e `buildMapaObrasAliases(rows)` extraídos de `src/lib/faturamento/upsert.ts`. Facilita testes unitários da regra de vinculação NFS-e ↔ obra sem tocar no banco.

### Reclassificações (`io` → `orchestration`)
Módulos que combinam múltiplas fontes de I/O (supabase + api legado) e/ou regras de negócio em torno da persistência:

- `src/lib/obras/sync.ts` — supabase (`obras`) + `api` (PHP `obras.flowcastId`).
- `src/lib/faturamento/upsert.ts` — supabase (obras/centros/faturamento_nfse) + regras de resolução/idempotência.
- `src/lib/ponto/pontoRepo.ts` — parse (`parseRelatorioCsv`) + regras (`isCentroIndireto`) + supabase.

Módulos puros de I/O foram mantidos como `io` (queries e writes diretos sem regras adicionais).
