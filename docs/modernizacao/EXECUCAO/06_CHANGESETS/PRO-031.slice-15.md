# PRO-031 · slice-15 — Numeração customizada em Requisições

## Contexto
Após aplicar `emitirNumeroCustomizado` em Cotação (slice-14), o próximo
documento com criação formal é a **Requisição**. A tabela `requisicoes` ainda
não possui coluna própria de número parametrizado — a associação
`requisicaoId -> número` fica no `documentoNumeracaoLocal` (localStorage),
mesma abordagem do slice-14. A sequência continua centralizada em
`empresaParametrizacaoRepo.emitirNumero`.

## Entrega
- `src/pages/suprimentos/Requisicoes.tsx`
  - Passa `id` pré-gerado (`crypto.randomUUID()`) no payload de criação.
  - Emite número via `emitirNumeroCustomizado(empresaAtualId, "requisicao")`
    antes do insert; faz `rollback()` se o insert falhar.
  - Registra em `documentoNumeracaoLocal` no sucesso e atualiza state
    `numeracoesDocumento` para refletir na UI sem reload.
  - Exibe badge com número emitido (`numeracaoLocal.numero`) na listagem;
    fallback `REQ-{id.slice(-6)}` para registros anteriores ao slice.
  - Toast de sucesso mostra o número emitido quando disponível.

## Escopo consciente
- Sem migração de schema — coluna persistente ficará para quando o modelo
  multiempresa deixar o localStorage.
- Sem alteração de RLS/policies.
- PDF de Requisição não existe hoje; nada a alterar em exportadores.

## Validação
- `bunx tsgo --noEmit`: limpo.
- `bunx vitest run src/lib/empresa/`: 11/11 verdes.
