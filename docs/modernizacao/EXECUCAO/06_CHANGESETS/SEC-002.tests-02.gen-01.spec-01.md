## 4. Contrato do gerador

### 4.1 Determinismo

- Ordenação alfabética estável por `(lote, tabela, caso)` antes de escrever.
- Newline `\n` (LF) fixo; sem CRLF.
- Encoding `utf-8` sem BOM.
- Nenhum timestamp, UUID, hostname, PID ou `Date.now()` no conteúdo gerado.
- Cabeçalho fixo `-- test_id: SEC-002.T-<lote>-<tabela>-<caso>` na linha 1.

### 4.2 Idempotência

- Rodar `gen-tests-02.mjs` **N** vezes produz byte-a-byte o mesmo write set.
- Arquivos preexistentes com conteúdo divergente são **sobrescritos** apenas fora do modo `--check`.
- Diretórios `batch-*/` são criados via `mkdir -p` equivalente; nunca removidos.

### 4.3 Modo `--check` (gate de CI)

- Não escreve. Compara conteúdo esperado × conteúdo atual byte-a-byte.
- Exit code `0` se idênticos; `1` se qualquer arquivo diverge ou está ausente; `2` para erro de entrada (CSV/spec ausente ou malformado).
- Saída legível: uma linha por divergência no formato `DIFF <caminho> expected=<sha256[:8]> got=<sha256[:8]>`.
- Também detecta **arquivos órfãos** (`batch-*/*.sql` sem `test_id` correspondente) — exit `1` com prefixo `ORPHAN`.

### 4.4 Preservação de artefatos legados

- **Preserva byte-a-byte** os agregados `supabase/tests/sec-002/batch-*/*_rls.sql` já existentes (arquivos cujo nome termina em `_rls.sql` e não contêm `__` no basename).
- Migração desses agregados para o novo formato fica para `SEC-002.tests-03`.
