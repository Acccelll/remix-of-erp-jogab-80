## 2. Invariantes verificados (R1–R7)

| Regra | Descrição executável |
|---|---|
| R1 | Todo consumidor listado em `apply-map.consumers[]` existe fisicamente no repositório. |
| R2 | Todo consumidor faz `import` de `./load-apply-map.mjs` (script) ou referencia `scripts/sec002/load-apply-map.mjs` (workflow). |
| R3 | Nenhum consumidor lê `.github/sec002-apply-map.json` diretamente (`readFile`, `require`, `fs.read*`, `cat`). |
| R4 | Nenhum consumidor redefine `SCHEMA_VERSION` — apenas o loader exporta. |
| R5 | Nenhum consumidor grava em `src/**`, `supabase/functions/**` ou `supabase/migrations/**`. |
| R6 | Todo consumidor emite `[sec002/<nome>] OK` em sucesso e `[sec002/<nome>] FAIL` em falha, com `exit(0|1)`. |
| R7 | `validate-dri-matrix.mjs` aparece como consumidor obrigatório e obedece R1–R6. |

## 3. Artefato 1 — `scripts/sec002/check-consumers.mjs`

**Caminho de destino:** `scripts/sec002/check-consumers.mjs`
**Encoding:** UTF-8, LF, sem BOM. Sem dependências externas. ESM puro. Node ≥ 20.

```js
#!/usr/bin/env node
// Guard determinístico do contrato de consumo do apply-map (R1–R7).
// Consome scripts/sec002/load-apply-map.mjs. Nunca lê o JSON diretamente.
import { readFileSync, existsSync } from "node:fs";
import { loadApplyMap, SCHEMA_VERSION } from "./load-apply-map.mjs";

const NAME = "sec002/consumers-guard";
const violations = [];
const push = (r, msg) => violations.push(`${r} ${msg}`);

const map = loadApplyMap();
if (map.schema_version !== SCHEMA_VERSION) {
  push("R0", `schema_version=${map.schema_version} != loader=${SCHEMA_VERSION}`);
}

const FORBIDDEN_WRITE = [/src\//, /supabase\/functions\//, /supabase\/migrations\//];
const FORBIDDEN_READ = [
  /readFile(Sync)?\s*\(\s*["'`][^"'`]*sec002-apply-map\.json/,
  /require\s*\(\s*["'`][^"'`]*sec002-apply-map\.json/,
  /fs\.(read|createReadStream)[A-Za-z]*\s*\(\s*["'`][^"'`]*sec002-apply-map\.json/,
  /cat\s+[^\n]*sec002-apply-map\.json/,
];

for (const c of map.consumers) {
  // R1
  if (!existsSync(c)) { push("R1", `consumidor ausente: ${c}`); continue; }
  const src = readFileSync(c, "utf8");
  const isScript = c.endsWith(".mjs");
  const isWorkflow = c.endsWith(".yml") || c.endsWith(".yaml");

  // R2
  if (isScript && !/from\s+["']\.\/load-apply-map\.mjs["']/.test(src)) {
    push("R2", `${c} não importa ./load-apply-map.mjs`);
  }
  if (isWorkflow && !/scripts\/sec002\/load-apply-map\.mjs/.test(src)) {
    push("R2", `${c} não referencia scripts/sec002/load-apply-map.mjs`);
  }

  // R3
  for (const re of FORBIDDEN_READ) {
    if (re.test(src)) push("R3", `${c} lê sec002-apply-map.json diretamente`);
  }

  // R4
  if (isScript && /(^|\s)(const|let|var|export\s+const)\s+SCHEMA_VERSION\s*=/.test(src)
      && !/load-apply-map\.mjs$/.test(c)) {
    push("R4", `${c} redefine SCHEMA_VERSION`);
  }

  // R5
  for (const re of FORBIDDEN_WRITE) {
    if (new RegExp(`(writeFile|createWriteStream|appendFile)[A-Za-z]*\\s*\\(\\s*["'\`][^"'\`]*`).test(src)
        && re.test(src)) {
      push("R5", `${c} grava em caminho proibido (${re})`);
    }
  }

  // R6
  if (isScript) {
    const base = c.split("/").pop().replace(/\.mjs$/, "");
    if (!new RegExp(`\\[sec002/${base}\\]\\s+OK`).test(src)) {
      push("R6", `${c} não emite [sec002/${base}] OK`);
    }
    if (!new RegExp(`\\[sec002/${base}\\]\\s+FAIL`).test(src)) {
      push("R6", `${c} não emite [sec002/${base}] FAIL`);
    }
    if (!/process\.exit\(\s*[01]\s*\)/.test(src)) {
      push("R6", `${c} não usa process.exit(0|1)`);
    }
  }
}

// R7
const dri = "scripts/sec002/validate-dri-matrix.mjs";
if (!map.consumers.includes(dri)) push("R7", `${dri} ausente em consumers[]`);

if (violations.length === 0) {
  console.log(`[${NAME}] OK`);
  process.exit(0);
}
console.error(`[${NAME}] FAIL`);
for (const v of violations) console.error(`  - ${v}`);
process.exit(1);
```

Contratos:

- Saída em sucesso: uma única linha `[sec002/consumers-guard] OK` em `stdout`, `exit 0`.
- Saída em falha: `[sec002/consumers-guard] FAIL` em `stderr`, uma violação por linha, `exit 1`.
- Nunca escreve em disco. Nunca faz rede. Nunca lê `.github/sec002-apply-map.json` diretamente.

## 4. Artefato 2 — `.github/workflows/sec002-consumers-guard.yml`

**Caminho de destino:** `.github/workflows/sec002-consumers-guard.yml`

```yaml
name: sec002-consumers-guard
on:
  pull_request:
    paths:
      - ".github/sec002-apply-map.json"
      - "scripts/sec002/**"
      - ".github/workflows/sec002-**.yml"
  push:
    branches: [main]
    paths:
      - ".github/sec002-apply-map.json"
      - "scripts/sec002/**"
      - ".github/workflows/sec002-**.yml"

concurrency:
  group: sec002-consumers-guard-${{ github.ref }}
  cancel-in-progress: true

jobs:
  guard:
    runs-on: ubuntu-latest
    timeout-minutes: 3
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
      - name: validate apply-map
        run: node scripts/sec002/validate-apply-map.mjs
      - name: check consumers
        run: node scripts/sec002/check-consumers.mjs
```

Contratos do workflow:

- Rodada obrigatória em qualquer PR que toque o apply-map, os scripts `scripts/sec002/**` ou workflows `sec002-*`.
- Precede semanticamente `sec002-pr-checklist`: se `consumers-guard` falha, o checklist é considerado indefinido e o PR é bloqueado.
- Sem cache. Sem segredos. Sem side effects fora do runner.

## 5. Tratamento de falso-positivos

1. Regex R3/R5 são deliberadamente restritas a `sec002-apply-map.json` e aos prefixos proibidos. Comentários que citem o caminho **não** disparam falso-positivo porque as regexes exigem a chamada de leitura/escrita associada.
2. Se um consumidor legítimo precisar de padrão novo (ex.: leitura via loader auxiliar), atualizar R42 primeiro e só então adicionar a exceção no guard — nunca o contrário.
3. `SCHEMA_VERSION` só pode ser definido em `load-apply-map.mjs`. Ferramentas auxiliares consomem via `import { SCHEMA_VERSION } from "./load-apply-map.mjs"`.

## 6. Interação com o pacote

- **R41/R47:** o guard depende do loader e do JSON canônicos. Mudança no loader exige rerodada do guard.
- **R42:** este arquivo é a implementação executável do contrato R1–R7; qualquer mudança em R42 obriga bump de R43 e nova materialização deste changeset.
- **R45 (DRI):** `validate-dri-matrix.mjs` é validado por R7 e pelas regras R1–R6 comuns.
- **`sec002-pr-checklist`:** roda depois deste guard; falha aqui bloqueia o checklist.
- **`sec002-freeze-guard`:** independente; ambos rodam em PRs de apply.
