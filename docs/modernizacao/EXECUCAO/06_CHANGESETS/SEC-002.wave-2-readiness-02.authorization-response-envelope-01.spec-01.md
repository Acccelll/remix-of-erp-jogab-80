# R224' — SEC-002 · Wave 2 Readiness · Authorization Response Envelope (spec)

**Tipo:** especificação · governança pura  
**Alvo:** envelope canônico de resposta para ciclos de continuidade sem intake GM/D-3 válido.  
**Baseline:** R208', R209', R210', R211', R212', R213', R214', R215', R216', R217', R218', R219', R220', R221', R222', R223'.  
**Data:** 2026-07-12.

## 1. Objetivo

Padronizar a resposta operacional mínima quando o input externo solicita continuidade (`Seguir`) mas não traz autorização formal GM/D-3. Este spec **não** cria ledger, **não** assina, **não** cria `GO-SEC-002-helpers-02-deploy-01.md`, **não** preenche §5 de `D-3-SEC-002.md`, **não** faz deploy de `helpers-02` e **não** aplica `helpers-03`.

## 2. Envelope obrigatório

Todo round de continuidade documental sob R223' deve encerrar com o envelope:

```text
ONDA ATUAL: WAVE 2 — OPEN; D-6 fechado; PC1..PC7 verdes; PC8/PC9 SKIP; bloqueios GM/D-3 preservados.
PRÓXIMO PASSO: aguardar intake formal conforme R218'/R220' ou avançar apenas governança documental que não materialize autorização.
```

O envelope é status, não autorização.

## 3. Campos permitidos

- **ONDA ATUAL:** pode citar estado da wave, gates PC1..PC9, bloqueios ativos e último round documental.
- **PRÓXIMO PASSO:** pode citar aguardos formais, próximos specs documentais ou critérios R218'/R220'.
- **Escopo:** deve declarar impacto em produção nulo quando não houver materialização.

## 4. Campos proibidos

- Não declarar `GO`, `NO-GO`, `D-3a`, `D-3b` ou `D-3c` como inferidos.
- Não prometer deploy/apply como próximo passo automático.
- Não instruir obtenção de chaves, senhas ou segredos.
- Não referenciar execução direta de SQL/migration/workflow sem round material autorizado.
- Não substituir documentos formais de decisão por texto de resposta.

## 5. Relação com R216'–R223'

1. R216' define que entrada genérica não é autorização.
2. R217' define templates futuros, não preenchidos por este envelope.
3. R218' define checklist; o envelope só aponta para ele.
4. R219' classifica entradas inválidas; o envelope não materializa rejeição se não houver intake formal.
5. R220' define reenvio completo; o envelope pode solicitá-lo.
6. R221' define ledger futuro; o envelope não cria entrada.
7. R222' roteia mensagens; o envelope é saída de `SEM AUTORIZAÇÃO`.
8. R223' fixa o estado de espera; o envelope é sua forma textual canônica.
