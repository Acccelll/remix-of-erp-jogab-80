**Onda:** 2 (OPEN — gate operacional PC1..PC7 verde por R136; `EXPECTED_INDEX_ROWS = 31`)
**Data:** 2026-07-12
**Escopo:** especifica o **segundo apply autorizado** do write set da Onda 2 —
materializar o diretório executável `supabase/tests/sec-002/` e o runner
`scripts/db/run-sec-002-tests.sh` conforme o contrato imutável de
`SEC-002.tests-02.suite.spec-01` (§§1–7). Este changeset **não executa** a
suíte, **não** altera policies, **não** aplica SQL ao banco. Ele apenas fixa o
contrato do apply e as invariantes AT1–AT14 que a materialização subsequente
(`materialize-01`) precisará satisfazer.

## 1. Pré-condições duras

O apply só pode ser materializado se **todas** verdadeiras:

1. Onda 2 `OPEN` — `.github/sec002-readiness/wave-2.md` com bloco canônico de
   R95 §3 (garantido por R127).
2. `node scripts/sec002/verify-wave-2-preconditions.mjs --json` → `PC1..PC7 =
   OK` contra `main` no SHA imediatamente anterior ao apply (gate reativado
   por R136; `EXPECTED_INDEX_ROWS = 31`).
3. `SEC-002.tests-02.suite.spec-01` (contrato lógico da suíte) presente e
   imutável no repositório (referência R22).
4. Predecessor `helpers-02-apply-01` presente com selo completo:
   apply (R132) + self-register (R134) + bump PC4 (R136).
5. `INDEX.md` estável em 31 linhas úteis; nenhum apply fora da ordem
   `helpers-02 → tests-02-suite → batch-B → batch-C → batch-D → batch-E →
   post-rls-handoff` foi iniciado.
6. Nenhuma migração de lote B/C/D/E aplicada em produção.

Se qualquer item falhar, o apply é abortado sem escrever bytes.

## 3. Invariantes AT1–AT14

- **AT1** — Diretório-raiz da suíte é exatamente `supabase/tests/sec-002/`;
  nenhum arquivo criado fora dele exceto o runner `scripts/db/run-sec-002-tests.sh`
  e o manifest em `.github/sec002-evidence/tests-02-suite-apply-01/`.
- **AT2** — Layout físico bate `SEC-002.tests-02.suite.spec-01` §1
  (diretórios `_lib/`, `helpers/`; **sem** `batch-B/…batch-E/` neste apply-01).
- **AT3** — Cada arquivo `_lib/*.sql` contém apenas DDL/DML utilitário
  (macros, seeds, jwt helpers, teardown); nenhum `create policy`, nenhum
  `alter table`, nenhum `grant`.
- **AT4** — Cada arquivo `helpers/user_in_<x>.sql` segue o esqueleto §4
  (`begin;` → `\i _lib/fixtures.sql` → `\i _lib/jwt.sql` → ATO → ORÁCULO →
  `rollback;`) e emite `-- OK: SEC-002.T-H-<slug>-<n>` por assert.
- **AT5** — Soma de asserts nos 4 arquivos `helpers/*` = 15 (3+3+4+5),
  bate com `SEC-002.helpers-01` §6.
- **AT6** — Runner `run-sec-002-tests.sh` usa `psql -v ON_ERROR_STOP=1`,
  itera em ordem alfabética por subpasta, e implementa a ordem estrita §3:
  `helpers/` primeiro; ausência de `batch-*/` **não** é erro (delegado a apply-02).
- **AT7** — Runner recusa executar contra produção — exige `PGDATABASE` ≠
  banco de produção e `SEC002_ALLOW_STAGING=1`.
- **AT8** — Runner valida pré-condições §2 do spec-01 antes do primeiro
  assert: (a) 4 helpers presentes em `pg_proc`; (b) `pgcrypto` disponível.
  A verificação de "policy do lote sob teste" é **skip** neste apply-01
  (nenhum lote presente).
- **AT9** — Nenhum arquivo excede 120 linhas; nenhum uso de extensão externa
  (pgTAP, plpgsql_check).
- **AT10** — Zero mutação em `supabase/migrations/`; zero `create policy`;
  zero `grant`; zero `drop function`.
- **AT11** — Manifest `tests-02-suite-apply-01/manifest.json` com
  `schema_version: v2026-07-12.4`, `apply_id: tests-02-suite-apply-01`,
  `verifier_gate: on`, `refs` incluindo `R22, R132, R136`,
  `invariants_verified: AT1..AT14`, hashes SHA-256 dos 10 arquivos do write
  set (excluindo o próprio manifest).
- **AT12** — `node scripts/sec002/verify-wave-2-preconditions.mjs --json`
  continua `PC1..PC7 = OK` após o apply (novos arquivos não invalidam
  `INDEX.md` — a linha 32 só entra em `self-register-01`).
- **AT13** — `apply-map` **não** é editado; consumers guard permanece verde.
- **AT14** — Nenhum arquivo do write set contém segredos, URLs de produção
  ou tokens; strings de conexão só via env vars.

## 4. Efeito no banco

**Nenhum neste changeset e nenhum no `materialize-01`.** A suíte é apenas
gravada como artefato versionado. A execução real contra staging fica
condicionada a:

1. `helpers-02` migração deployada em staging (dependência AT8-a).
2. Janela de execução declarada por DRI GM `Cappucceno`.
3. `SEC002_ALLOW_STAGING=1` explicitamente exportado.

## 5. Rollback do apply (não da suíte)

Se `materialize-01` for revertido antes de qualquer execução, basta remover
os 11 arquivos do write set (§2). O `INDEX.md` volta ao estado de R136 sem
efeito colateral. Nenhum estado no banco é criado por este apply.
