# PRO-027 · slice-03 — Gatilho de vencimento e presets por template

**Onda:** 07 · **Achado:** PRO-027 · **Depende de:** slice-02 (painel + ação `adicionar_label`).

## Contexto

Slice-02 cobriu apenas o gatilho `card_movido_para_lista`. Este slice
fecha o catálogo mínimo prometido pelo achado adicionando o gatilho
por prazo (`card_vencendo`) e um conjunto de presets sugeridos por
template de quadro, para o usuário partir de exemplos úteis em vez
da tela em branco.

## Entrega

- `src/lib/board/automacoes.ts`:
  - `AutomacaoGatilho` agora aceita `{ tipo: "card_vencendo",
    diasAntes: number }`.
  - `runOnVencimento(regras, cards, { boardId, hoje })` — puro:
    devolve `AcaoAgendada[]` (`{ cardId, regraId, acao }`). Considera
    `delta ≤ diasAntes` (inclui cards já vencidos).
  - `presetsForTemplate(templateId)` — sugestões para `obras`
    (aviso de bloqueio + alerta 3 dias antes) e `crm` (follow-up
    hoje); default genérico para os demais templates.
- `src/components/board/BoardAutomacoesDialog.tsx`:
  - Novo dropdown **Gatilho** (`Card entra na lista…` ou
    `Card vencendo em N dias`).
  - Campo `diasAntes` (input numérico 0–90) quando gatilho é
    `card_vencendo`; alternar gatilho reseta o campo dependente.
- `src/lib/board/__tests__/automacoes.test.ts` — +4 casos:
  janela cobre próximos dias, inclui vencidos, `obras` traz vencimento,
  template desconhecido cai no default.

## Escopo consciente

- **Execução periódica** de `runOnVencimento` não foi ligada ainda no
  QuadroBoard — o motor está pronto e testado; o disparo (uma vez ao
  entrar no board, com dedup por sessão) fica em `slice-04` para
  evitar toasts repetidos sem observar antes o volume real.
- Presets ficam apenas expostos via `presetsForTemplate`. Botão
  "Aplicar sugestões" no painel entra junto do slice-04.
- `listaId` vazio nos presets é intencional: o consumidor deve
  substituir pelo id da lista alvo do quadro concreto.
