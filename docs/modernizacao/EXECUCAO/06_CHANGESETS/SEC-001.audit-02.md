## 2. Duas rotas paralelas de sincronização

O código cliente tem **duas implementações** do mesmo self-heal, cada uma chamando uma edge function diferente:

### Rota A — `ensureCloudSession` → `provision-auth-user`

- Localização: `src/lib/auth/ensureCloudSession.ts`.
- Email: prefere `player.email` real; fallback `${login}@obraflow.local` (rejeita `@obraflow.local` como "válido" via `validEmail`).
- Payload: `{login, email, password, is_gm, acessos}` — carrega RBAC completo.
- Consumidor: `EmpresaContext` (queries `empresas`, `user_empresas`, `obras`).

### Rota B — `ensureSupabaseSession` → `sync-player-auth`

- Localização: `AppContext.tsx:353-376`.
- Email: hard-coded `${login}@planifik.local` — **domínio diferente** de A.
- Payload: `{login, senha}` — sem RBAC; depende do trigger `handle_new_user`.
- Consumidor: `AppContext.login` (linha 405) + hydrate em reload (linha 311).

**Consequência crítica para o cutover:** o mesmo `login` pode ter dois `auth.users` distintos (`@obraflow.local` e `@planifik.local`) dependendo de qual rota disparou primeiro. Confirma o achado #1 de `audit-01` e amplia: o problema não é só server-side, é a **inconsistência cliente** que produz o duplicado.

## 3. Fluxo atual de `AppContext.login` (linhas 378–427)

```
1. api.create("login", {username, password})            // PHP legado — fonte da verdade
2. Se OK:
   a. Compõe Player (id, login, senha em claro, email, isGM, acessos)
   b. setCurrentPlayer + localStorage.setItem("go_token", result.token)
   c. ensureSupabaseSession(u, p)  → Rota B (fire-and-forget)
   d. loadAll()
3. Se PHP falhou: fallback a players locais (lista em memória)
   → ensureSupabaseSession(u, p) → Rota B (fire-and-forget)
```

Pontos de atenção:

- **Senha em claro persistida** em `localStorage.go_player` (`useEffect` linha 323–326) — necessária hoje para re-sincronizar Supabase em reload (linha 308–314), mas é vetor de vazamento até o cutover.
- **`ensureSupabaseSession` é fire-and-forget** — falha silenciosa deixa o usuário logado no PHP sem sessão Cloud; queries Supabase quebram por RLS. `EmpresaContext` reage a isso disparando `ensureCloudSession` (Rota A) sob demanda, gerando a duplicação de identidade acima.
- **Fallback a `players` locais** (linha 416) — permite login sem PHP quando há lista local; nesse caminho `token` não é setado, o que quebra `loadAll` (guarda de `go_token` na linha 301 em reloads futuros).

## 4. Logout (linhas 429–433)

```
setCurrentPlayer(null)
localStorage.removeItem("go_token")
supabase.auth.signOut()   // fire-and-forget
```

Não limpa `go_player` (é feito pelo `useEffect` reativo, linha 325). Não invalida o token PHP no servidor. Não notifica `EmpresaContext` além do rerender natural.

## 5. Consumidores de `currentPlayer.isGM`

- **37 arquivos** referenciam `isGM` (medido via `rg -l "isGM|currentPlayer\.isGM" src | wc -l`).
- Categorias:
  - **Contextos:** `AppContext`, `EmpresaContext`, `app/mappers`, `app/helpers`, `app/usePlayersState`.
  - **Hooks de permissão:** `useCardPermissions`, `useObrasEditaveis`, `useObraMembership`.
  - **Empresa:** `EmpresaSelector`, `EmpresaScopeBadge`.
  - **Páginas (bypass GM):** `Obras`, `Patrimonios`, `QuadroBoard`, `QuadroContratos`, `Colaboradores`, `Insumos`, `Orcamento`, `GruposNegociacao`, `Composicoes`, `Recebimento`, `Riscos`, `PacotesTrabalho`, `NaoConformidades`, `Quadros`.
  - **Diálogos:** `CardGenericoDialog`, `ImportarTrelloDialog`, `CenariosSheet`, `ImportValidationReport`.

O cutover precisa preservar o invariante `currentPlayer.isGM ⇔ has_role(auth.uid(), 'gm')` para não quebrar nenhum desses 37 pontos. A migração deve garantir espelhamento em `public.user_roles` antes de flipar o consumo.

## 7. Recomendações (para virar changesets no cutover)

Estas ações **não são executadas agora** — Onda 2 em NO-GO. Servem para orientar o pacote de cutover.

1. **SEC-001.g** — Colapsar Rota A e Rota B em um único helper `ensureCloudSession` (única fonte da verdade do email + RBAC). Deprecar `ensureSupabaseSession` in-line em `AppContext`.
2. **SEC-001.h** — Migration prévia de conciliação: para cada `auth.users` com email `@planifik.local`, encontrar o par `@obraflow.local`/email real e consolidar em um único id; atualizar FKs em `profiles`/`user_empresas`/`user_roles`.
3. **SEC-001.i** — Remover persistência de senha em claro em `localStorage.go_player`; hydrate de sessão em reload passa a depender **exclusivamente** de `supabase.auth.getSession()` (que já persiste refresh token de forma segura via SDK).
4. **SEC-001.j** — `AppContext.login` passa a chamar `supabase.auth.signInWithPassword` diretamente; `api.create("login", ...)` vira **fallback temporário** com feature-flag e é deletado ao final da Onda 2.
5. **SEC-001.k** — `currentPlayer` deixa de ser fonte da verdade de RBAC; hooks de permissão migram para consultar `public.user_roles` via `has_role()` (padrão D-2). `isGM` continua no tipo durante a transição, mas alimentado pelo servidor.
6. **SEC-001.l** — Logout: `supabase.auth.signOut()` deixa de ser fire-and-forget; awaited + limpa `go_player`/`go_token` explicitamente.
