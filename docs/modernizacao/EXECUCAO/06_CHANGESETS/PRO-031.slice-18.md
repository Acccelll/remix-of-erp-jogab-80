# PRO-031 · slice-18 — Numeração customizada em Contratos

## Contexto
Slice-17 fechou a UI de parametrização para os tipos existentes. Falta ligar
Contratos à emissão customizada — o tipo `contrato` já existia em
`TipoDocumentoNumeravel` e no dialog, mas o fluxo de criação não emitia
número parametrizado.

Complicação: `ContratosStateProvider` fica acima de `EmpresaProvider` na
árvore de `App.tsx`, então `useEmpresa()` lançaria. Solução: expor variante
tolerante `useEmpresaOptional` que retorna `null` fora do provider.

## Entrega
- `src/contexts/EmpresaContext.tsx`
  - Adicionado `useEmpresaOptional()` — não lança quando fora do provider.
- `src/contexts/contratos/ContratosStateContext.tsx`
  - Consome `empresaAtualId` via `useEmpresaOptional` + ref para leitura
    estável dentro do callback.
  - `addContrato` mantém assinatura `void` (fire-and-forget compatível com
    todos os callers atuais).
  - Fluxo interno: emite número via `emitirNumeroCustomizado(empresaId,
    "contrato")` → `mutateAsync(novo)` → registra em
    `documentoNumeracaoLocal` com o `id` retornado no sucesso; faz
    `rollback()` no `catch`.

## Escopo consciente
- Sem exposição do número na UI (list/detalhe) — próximo slice.
- Sem alteração da UI de importação em massa (`XLSX`), que também dispara
  `addContrato` — cada linha emite seu número normalmente.
- Recebimento e Nota Fiscal continuam dependendo de refatoração (RPC atômica
  / novo modelo persistente).
