# SEC-002.consumers-guard-01.spec-01 — CI guard de consumo do apply-map

**Onda:** 2 (bloqueada — depende de `SEC-001` fechar e da abertura formal da Onda 2)  
**Data:** 2026-07-12  
**Depende de:** `SEC-002.apply-map-01.spec-01` (R40), `SEC-002.apply-map-01.materialize-01` (R41), `SEC-002.apply-map-01.consumers-01.spec-01` (R42)  
**Escopo:** especificar o workflow CI `sec002-consumers-guard` que prova, a cada PR, as invariantes R1–R6 de R42, impedindo a reintrodução de hardcode do apply-map em qualquer consumidor. **Nenhum arquivo de produção alterado.**

## 1. Racional

R42 estabeleceu as regras de consumo. Sem CI guard, uma refatoração pode reintroduzir `readFileSync('.github/sec002-apply-map.json')`, listas duplicadas ou contagens hardcoded sem que ninguém perceba antes de um apply em produção. Este guard é a rede de segurança automatizada.

## 2. Artefatos

- **Workflow:** `.github/workflows/sec002-consumers-guard.yml`
- **Script:** `scripts/sec002/check-consumers.mjs`
- **Trigger:** `pull_request` em branches que tocam `scripts/sec002/**`, `.github/workflows/sec002-*.yml` ou `.github/sec002-apply-map.json`; e `push` em `main`.
- **Status obrigatório:** required check no branch protection do `main`.

## 3. Contrato do `check-consumers.mjs`

ESM puro, sem dependências. Executa as seis invariantes de R42 §5 e retorna `0` (todas ok) ou `1` (qualquer violação).

Invariantes implementadas:

| Regra | Verificação |
|---|---|
| R1 | `rg -n "sec002-apply-map\.json" scripts/sec002` retorna apenas `load-apply-map.mjs`. |
| R2 | `rg -n "readFileSync\(.*sec002-apply-map" scripts/sec002` retorna apenas `load-apply-map.mjs`. |
| R3 | Em `scripts/sec002/validate-*.mjs`, os literais `"helpers-02"`, `"tests-02-suite"`, `"batch-B"`..`"batch-E"` só podem aparecer dentro de strings de mensagem/log (linha começa com `console.` ou é parte de template `[sec002/...]`); nunca em `if`/`switch`/`===`/`case`. Detecção por regex de contexto sintático (linha contém `===`, `case `, `switch(` na mesma linha do literal → falha). |
| R4 | Em `scripts/sec002/validate-*.mjs`, ausência das strings/números-tabu `15`, `39`, `92`, `75`, `110`, `331`, `462` como literais isolados (regex `\b(15\|39\|92\|75\|110\|331\|462)\b`). Whitelist: comentários com `// eslint-disable-line sec002-hardcode` (nunca deve existir em produção — grep secundário rejeita seu uso). |
| R5 | `rg -n "sec002-apply-map" .github/workflows` sem matches com `jq` na mesma linha. |
| R6 | Cada arquivo `scripts/sec002/validate-*.mjs` contém `import ... from "./load-apply-map.mjs"`. |

Formato de saída (padrão R42 §4):

```
[sec002/consumers-guard] FAIL
 - R3 em scripts/sec002/validate-go-no-go.mjs:42: uso de literal "batch-B" fora de contexto de log
[sec002/consumers-guard] OK
```

Códigos: `0` OK, `1` violação, `2` erro operacional.

## 4. Workflow `.github/workflows/sec002-consumers-guard.yml` (esqueleto canônico)

```yaml
name: sec002-consumers-guard
on:
  pull_request:
    paths:
      - "scripts/sec002/**"
      - ".github/workflows/sec002-*.yml"
      - ".github/sec002-apply-map.json"
  push:
    branches: [main]
    paths:
      - "scripts/sec002/**"
      - ".github/workflows/sec002-*.yml"
      - ".github/sec002-apply-map.json"
jobs:
  guard:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20" }
      - name: Validate apply-map schema
        run: node scripts/sec002/validate-apply-map.mjs
      - name: Guard consumers (R1–R6)
        run: node scripts/sec002/check-consumers.mjs
```

## 5. Interação com outros guards

- **`sec002-freeze-guard`:** independente. Freeze bloqueia mudanças em `supabase/migrations/**`; consumers-guard bloqueia degradação de `scripts/sec002/**`. Um PR pode ser bloqueado por ambos.
- **`sec002-pr-checklist`:** consome o apply-map indiretamente; se este guard falhar por R6 (import ausente), o checklist também falhará no passo `validate-apply-map`. Ordem de execução em CI: `validate-apply-map` → `consumers-guard` → demais validadores.
- **Errata:** violação de R1–R6 em produção exige errata `severity=high`, `gm_required=true`, `category=policy_rls` (subcategoria `apply-map-hardcode`), com rollback do commit ofensor antes de qualquer novo apply.

## 6. Falso-positivos previstos e tratamento

- **Números `15`/`39`/… em nomes de arquivo de teste** (ex.: `test_39_...sql`) — irrelevante: guard opera apenas em `scripts/sec002/validate-*.mjs`, não em `supabase/tests/**`.
- **Comentário histórico citando contagens** — tratado como violação; usar referência textual (`totals.sum_expected_asserts`) em vez do número.
- **Mensagem de log incluindo `apply_id`** — permitido pois vem de `getApply(id).apply_id`, não de literal.

## 7. Impacto em produção

**Nenhum.** Especificação normativa. Não grava workflow, script ou config. Materialização em `SEC-002.consumers-guard-01.materialize-01` posterior.
