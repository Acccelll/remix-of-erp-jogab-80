# R219' — SEC-002 · Wave 2 Readiness · Authorization Negative Cases (spec)

**Tipo:** especificação · governança pura  
**Alvo:** matriz canônica de casos inválidos para intakes GM/D-3, consumindo R216' (contrato), R217' (templates) e R218' (checklist).  
**Baseline:** R208', R209', R210', R211', R212', R213', R214', R215', R216', R217', R218'.  
**Data:** 2026-07-12.

## 1. Objetivo

Fixar, de forma auditável, quais entradas externas **não** podem ser interpretadas como autorização válida para materializar assinatura GM, assinatura D-3, deploy de `helpers-02` ou apply de `helpers-03`. Este spec **não** assina, **não** cria `GO-SEC-002-helpers-02-deploy-01.md`, **não** preenche §5 de `D-3-SEC-002.md`, **não** faz deploy e **não** aplica SQL.

## 2. Casos inválidos GM

Um intake direcionado a `helpers-02.deploy-01` é inválido quando qualquer caso abaixo ocorrer:

| Caso | Exemplo textual | Motivo de rejeição | Efeito |
|---|---|---|---|
| GM-N1 | `Seguir` | Não contém decisão `GO`/`NO-GO`, assinante, papel, data ISO-8601, hash R208' nem janela/rollback. | Nenhum; R213' segue aguardando. |
| GM-N2 | `GO` isolado | Decisão sem alvo, assinatura, baseline e evidência PC1..PC7. | Nenhum; R213' segue aguardando. |
| GM-N3 | `GO helpers-02` | Alvo impreciso; alvo canônico precisa ser exatamente `helpers-02.deploy-01`. | Nenhum; R213' segue aguardando. |
| GM-N4 | `GO e NO-GO` | Decisão dupla viola XOR do checklist R218' §2. | Nenhum; R213' segue aguardando. |
| GM-N5 | `GO` com data local ambígua | Data não ISO-8601 UTC (`YYYY-MM-DDTHH:MM:SSZ`). | Nenhum; R213' segue aguardando. |
| GM-N6 | `GO` sem rollback owner | Campo obrigatório ausente para decisão `GO`. | Nenhum; R213' segue aguardando. |
| GM-N7 | `GO` com segredo/chave/senha no corpo | Intake contaminado por segredo; deve ser rejeitado e refeito sem exposição. | Nenhum; R213' segue aguardando. |

## 4. Regra de contenção

Se um intake inválido for recebido, o próximo round permitido é apenas documental e deve:

1. registrar a rejeição como governança pura, se necessário;
2. preservar R213' e R214' sem materialização;
3. não criar/preencher documentos de decisão;
4. não alterar `supabase/`, `src/`, `.github/sec002-evidence/INDEX.md`, verifier, apply-map, workflows ou banco;
5. apontar novamente para R216'–R218' como contrato de correção do intake.

1. Ciclo puramente documental; zero assinatura, deploy, apply ou execução de SQL/migration.  
2. R213', R214', R216', R217' e R218' preservados byte-a-byte.  
3. `GO-SEC-002-helpers-02-deploy-01.md` **não** criado neste ciclo.  
4. §5 de `03_DECISOES/D-3-SEC-002.md` permanece vazio.  
5. `SEC-002.inventory-02.csv` preservado (hash `8c18a694442e…d66a404ef`).  
6. `.github/sec002-evidence/INDEX.md` permanece com 45 linhas; `EXPECTED_INDEX_ROWS=45`.  
7. `Apply-map: v2026-07-12.4` preservado; `verify-wave-2-preconditions.mjs --json` continua verde em PC1..PC7 (PC8/PC9 SKIP).
