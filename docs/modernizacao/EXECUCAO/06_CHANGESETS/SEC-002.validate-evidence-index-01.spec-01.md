# SEC-002.validate-evidence-index-01.spec-01 — Validador do índice canônico de evidências

**Onda:** 2 (bloqueada — depende de `SEC-001` fechar e da Onda 2 ser formalmente aberta)
**Data:** 2026-07-12
**Depende de:**
- `SEC-002.evidence-archive-01.spec-01` (R38) — contrato geral de evidências e manifests;
- `SEC-002.apply-map-01.parser-bump-01.materialize-01` (R53) — loader corrente e `SCHEMA_VERSION = v2026-07-12.3`;
- `SEC-002.evidence-index-01.spec-01` (R58) — invariantes E1–E8;
- `SEC-002.evidence-index-01.materialize-01` (R59) — conteúdo canônico de `.github/sec002-evidence/INDEX.md`.

**Escopo:** especificar o consumidor executável `scripts/sec002/validate-evidence-index.mjs`, responsável por validar o índice `.github/sec002-evidence/INDEX.md` contra E1–E8 de R58 e contra o conteúdo canônico de R59. **Nenhum arquivo de produção é alterado nesta spec.** Materialização do script ocorre em `SEC-002.validate-evidence-index-01.materialize-01` (R61).

## 1. Racional

R58 definiu o índice único de evidências e R59 congelou seu conteúdo canônico. Falta especificar um validador determinístico para impedir drift entre:

- versão declarada no cabeçalho do índice;
- `SCHEMA_VERSION` do loader vigente;
- manifests realmente presentes;
- changesets docs referenciados;
- ordem append-only das linhas.

O validador garante que o índice seja auditável sem duplicar `hashes{}` ou `checks[]` dos manifests.

## 2. Artefato previsto

- **Script:** `scripts/sec002/validate-evidence-index.mjs`
- **Entrada:** sem argumentos obrigatórios; por padrão valida `.github/sec002-evidence/INDEX.md`.
- **Fonte de versão:** `import { SCHEMA_VERSION } from "./load-apply-map.mjs"`.
- **Fonte canônica de ordem:** tabela materializada em R59 §2, congelada no próprio validador até o bump `v2026-07-12.4`.
- **Sem dependências externas:** Node ≥ 20, ESM puro, apenas módulos `node:fs`, `node:path` e `node:crypto` se necessário para normalização futura.

## 3. Contrato CLI

```bash
node scripts/sec002/validate-evidence-index.mjs
node scripts/sec002/validate-evidence-index.mjs --file .github/sec002-evidence/INDEX.md
```

Parâmetros:

| Parâmetro | Obrigatório | Descrição |
|---|---:|---|
| `--file <path>` | não | Caminho alternativo para teste local. Em CI deve ser `.github/sec002-evidence/INDEX.md`. |

Saída:

```text
[sec002/validate-evidence-index] OK
```

ou:

```text
[sec002/validate-evidence-index] FAIL
 - E_EVIDX_E4 em linha 7: manifest ausente .github/sec002-evidence/parse-apply-id-01/manifest.json
```

Exit codes:

| Código | Significado |
|---:|---|
| `0` | E1–E8 válidas |
| `1` | violação de invariante `E_EVIDX_E1..E8` |
| `2` | erro operacional: argumento inválido, I/O inesperado ou parser sem tabela |

## 4. Invariantes executáveis

| Código | Invariante | Verificação normativa |
|---|---|---|
| `E_EVIDX_E1` | arquivo único | existe exatamente um arquivo de nome `INDEX.md` em `.github/sec002-evidence/`; em CI, `--file` diferente desse caminho falha. |
| `E_EVIDX_E2` | versão do cabeçalho | linha `Apply-map: vYYYY-MM-DD.N` existe e é idêntica a `SCHEMA_VERSION`. |
| `E_EVIDX_E3` | `apply_id` único | coluna `apply_id` não contém duplicatas e não contém valor vazio. |
| `E_EVIDX_E4` | manifest físico e JSON válido | cada caminho da coluna `manifest` existe, termina em `/manifest.json` e faz parse JSON sem erro. |
| `E_EVIDX_E5` | changeset docs físico | cada caminho da coluna `changeset docs` existe em `docs/modernizacao/EXECUCAO/06_CHANGESETS/` e termina em `.md`. |
| `E_EVIDX_E6` | refs mínimas | coluna `refs` contém pelo menos um token `R\d+` correspondente ao Rxx do changeset materializado da linha. |
| `E_EVIDX_E7` | ordem imutável | as 10 linhas iniciais são byte-a-byte equivalentes à ordem de R59 §2; linhas futuras só podem aparecer após a linha 10. |
| `E_EVIDX_E8` | timestamp UTC | `Última atualização` é ISO-8601 UTC (`YYYY-MM-DDTHH:mm:ssZ`) e não pode ser anterior ao timestamp congelado em R59 (`2026-07-12T00:00:00Z`). |

## 5. Parser normativo

O script deve tratar `.github/sec002-evidence/INDEX.md` como Markdown determinístico:

1. Ler o arquivo em UTF-8.
2. Rejeitar BOM.
3. Localizar exatamente uma tabela cujo cabeçalho seja:
   ```markdown
   | # | apply_id | manifest | changeset docs | schema | refs |
   |---|---|---|---|---|---|
   ```
4. Parsear linhas `| ... |` preservando ordem.
5. Normalizar espaços laterais de cada célula, sem alterar conteúdo interno.
6. Validar que colunas extras ou ausentes resultem em `E_EVIDX_E7`.
