# PRO-007.slice-01 — Núcleo puro do workflow de Não Conformidades

**Onda:** 07 · `PRO-007`
**Achado-base:** PRO-007 — "NC sem workflow ativo (sem responsável/prazo/reinspeção/notificação)".
**Dependência satisfeita:** `PRO-030` (Central de Notificações — closeout).
**Escopo desta fatia:** só o modelo puro (FSM + regras). Sem UI, sem repositório, sem notificação.

## Problema
Hoje a tabela `nao_conformidades` só carrega `status` (`aberta | em_tratativa | resolvida | cancelada`) — sem responsável obrigatório, prazo com validação, tratativa registrada nem reinspeção. As transições ficam a cargo de cada tela, o que abriu caminho para NCs "resolvidas" sem correção comprovada.

## Entrega
1. **`src/lib/inspecoes/nc-workflow.ts`** (`@module-kind pure`)
   - `NCStatus` estende o legado com `aguardando_reinspecao`.
   - `NCState` guarda `responsavelId`, `prazoISO`, `tratativa`, resultado da reinspeção e datas de encerramento.
   - `NCEvent`: `atribuir | registrar_tratativa | solicitar_reinspecao | reinspecionar | cancelar` (todos com `nowISO` — sem `Date.now()`).
   - `transition(state, event)` devolve `{ ok, state } | { ok, error }` cobrindo:
     - `atribuir` exige responsável não vazio, prazo parseável e no futuro.
     - `registrar_tratativa` exige texto não vazio, só em `em_tratativa`.
     - `solicitar_reinspecao` exige tratativa registrada.
     - `reinspecionar` aprovada → `resolvida` (`encerradaEmISO`); reprovada → volta a `em_tratativa` com resultado.
     - `cancelar` bloqueado após estado final, exige motivo.
   - `diasAteVencimento` / `estaVencida` calculados a partir de `nowISO` (sem `Date.now`).
2. **`__tests__/nc-workflow.test.ts`** — 7 casos cobrindo estado inicial, validações de atribuição, ciclo tratativa→reinspeção, reprovação vs aprovação, cancelamento e cálculo de vencimento.

## Validação
- `bunx vitest run src/lib/inspecoes/__tests__/nc-workflow.test.ts` → **7/7 verdes**.
- `bunx tsgo --noEmit` limpo.

## Fora de escopo
- **slice-02:** repositório + página `NaoConformidades.tsx` consumindo o workflow (mapeia `aguardando_reinspecao` no persistido; ver mapping legado).
- **slice-03:** gatilho de notificação via central `PRO-030` (atribuição, prazo próximo, vencimento, reprovação).
- **slice-04:** relatório/board de NCs vencidas.
