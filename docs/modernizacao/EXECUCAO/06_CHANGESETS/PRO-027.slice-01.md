# PRO-027 · slice-01 — Motor mínimo de automações de Board

**Onda:** 07 · **Achado:** PRO-027 · **Módulo:** M2 (Quadros).

## Contexto

Boards hoje só disparam "lembrete de prazo". O achado pede automações
por regra. Este slice entrega o **motor**: modelo declarativo,
persistência local, avaliação pura por gatilho e execução plugada no
único hook por onde todo o app move card entre listas
(`useUpdateCardBoardPosicaoListaEPosicao`). UI de gestão de regras
fica para `slice-02`.

## Entrega

- `src/lib/board/automacoes.ts` (novo):
  - Tipos `Automacao`, `AutomacaoGatilho`, `AutomacaoAcao`.
  - Gatilho suportado: `card_movido_para_lista`.
  - Ação suportada: `notificar` (mensagem).
  - `automacoesRepo` → `listByBoard`, `upsert`, `remove`,
    persistência em `localStorage` (`gestaobra:board:automacoes`).
  - `runOnMove(regras, ctx)` puro: filtra `ativa` + `boardId` +
    `listaId` e devolve as ações a executar.
- `src/lib/board/__tests__/automacoes.test.ts` — 3 casos: match,
  filtros (ativa/board/lista), persistência por board.
- `src/hooks/useCards.ts` — `useUpdateCardBoardPosicaoListaEPosicao`
  ganha `onSuccess` que chama `runOnMove(...)` e executa cada ação
  (`notificar` → `toast.message`). Falhas do motor não quebram o
  move (best-effort dentro de `try/catch`).

## Escopo consciente

- Sem UI ainda — regras existem só via API do repo (slice-02).
- Único gatilho: mover entre listas. Prazos/etiquetas/data virão em
  slice futuro conforme demanda.
- Persistência local por dispositivo — alinhado ao padrão do app
  para regras de UX; migração para tabela ocorre quando surgir
  necessidade de compartilhar entre usuários.
- Movimentação entre boards (`useMoverCardBoardPosicaoParaBoard`)
  ainda não dispara automações — o slice-02 avaliará se faz sentido
  aplicar as regras do board de destino.
