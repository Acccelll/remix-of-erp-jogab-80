# OPS-001.a — CI gate mínimo (Onda 0)

**Onda:** 0 · **Categoria:** Operação/CI
**Cisão:** OPS-001 → **OPS-001.a** (gate mínimo, Onda 0) · OPS-001.b (cobertura obrigatória, Onda 1, depende de QC-001/QC-002)
**Relacionado:** SEC-003, DEP-xlsx-pin (D-06), G-02, G-04

## Problema

Sem CI, qualquer PR podia introduzir regressão de lint, tipos, testes, build ou re-resolver `xlsx` para a versão vulnerável do npm sem que ninguém percebesse antes do deploy.

## Ação

Novo workflow `.github/workflows/ci.yml` executado em `push` na `main` e em toda `pull_request`:

1. `bun install --frozen-lockfile` — falha se `bun.lockb` estiver dessincronizado do `package.json`.
2. **Gate xlsx** — lê `node_modules/xlsx/package.json` e falha se a versão resolvida não for `0.20.x` (satisfaz D-06 / DEP-xlsx-pin).
3. `bun run lint` (eslint).
4. `bunx tsc --noEmit` (typecheck).
5. `bun run test` (vitest run).
6. `bun run build` (vite build).

Concorrência agrupada por ref cancela runs obsoletos.

## O que fica fora (OPS-001.b, Onda 1)

- Threshold de cobertura obrigatório (depende de QC-001 / QC-002).
- Gate de tamanho de bundle.
- Publicação de artefatos e preview deploy.

## Critérios de aceite

- (a) workflow presente em `.github/workflows/ci.yml` ✅
- (b) todos os passos executáveis localmente com os mesmos comandos ✅
- (c) gate xlsx bloqueia downgrade para 0.18.x ✅
- (d) `frozen-lockfile` bloqueia lock dessincronizado ✅

## Discoveries

- **D-07:** typecheck usa `tsc` em vez de `tsgo` — CI GitHub não tem `tsgo` disponível; local pode continuar usando `tsgo` (mais rápido). Reavaliar em ARC/QC.
- **D-08:** falta cache de `~/.bun/install/cache` no workflow — otimização adiada para OPS-001.b.
