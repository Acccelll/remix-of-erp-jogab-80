# PRO-009 · slice-02 — Reversão automática ao cancelar OC de cotação

**Onda:** 07 · **Prioridade:** P1 · **Marco:** M7 · **Escopo:** ISOLADA

## Contexto
Após `slice-01`, uma cotação vencedora gera OC em rascunho e marca a
requisição como `atendida`. Se a OC era cancelada antes de emitir, a
requisição continuava travada em `atendida`, forçando ação manual para
reabrir a cotação.

## Entrega
Novo fluxo: cancelar OC em rascunho reverte automaticamente as
requisições vinculadas de `atendida` → `cotando`, reabrindo a cotação
para nova rodada. OCs já emitidas continuam bloqueadas para essa ação.

## Alterações

### `src/lib/repositories/suprimentos.ts`
Novo método `cancelarOcRascunho(ocId)`:
1. Valida `status = rascunho` e `emitida_em` nulo.
2. Lê `ordem_compra_itens.requisicao_id` únicos da OC.
3. Para cada requisição, atualiza `status = cotando` apenas quando
   ainda está `atendida` (idempotente / não sobrescreve outros estados).
4. Marca OC como `cancelada`.
5. Retorna `{ revertidas }` para telemetria/UX.

### `src/pages/suprimentos/OrdensCompra.tsx`
Handler `cancelar` passa a chamar `cancelarOcRascunho`. Toast informa a
quantidade de requisições reabertas quando maior que zero.

## Não escopo
- PRO-010 (comunicação com fornecedor).
- Consolidação multi-cotação em uma única OC.
- Reversão pós-emissão (requer cancelamento formal + estorno de
  committed cost — fora do slice).

## Validação
`bunx tsgo --noEmit` — OK.
