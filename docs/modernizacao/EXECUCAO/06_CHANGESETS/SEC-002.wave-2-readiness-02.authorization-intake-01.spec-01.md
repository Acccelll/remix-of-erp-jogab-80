## 1. Objetivo

Definir o contrato de **intake** para os próximos rounds que dependem de autorização
externa: GO GM de `helpers-02.deploy-01` e decisão D-3 de `helpers-03.apply-01`.

Este changeset não interpreta `Seguir`, “pode continuar”, “avance” ou instruções
genéricas como assinatura. Ele apenas fixa quais campos tornam uma próxima mensagem
apta a abrir um round de materialização documental conforme R213' ou R214'.

---

## 2. Regra de não-assinatura implícita

Nenhuma frase genérica de continuidade destrava bloqueios externos. Para fins da
Onda 2:

| Entrada | Efeito |
|---------|--------|
| `Seguir` | avança o roadmap documental seguro; **não assina** GM nem D-3 |
| `MANTENHA O PADRÃO` | preserva governança e invariantes; **não assina** |
| `ONDA ATUAL / PRÓXIMO PASSO` | pede status e próximo item; **não assina** |
| autorização com decisão explícita, papel, data e alvo | pode abrir materialização documental, se cumprir §3 ou §4 |

Assim, enquanto a entrada não trouxer decisão explícita válida, os bloqueios seguem:

1. GO GM pendente para `helpers-02.deploy-01`.
2. D-3 pendente para `helpers-03.apply-01`.

---

## 3. Intake mínimo para GO GM

Para abrir `SEC-002.helpers-02.deploy-01.go-sign-01.materialize-01`, a mensagem ou
artefato de autorização deve conter, no mínimo:

| Campo | Regra |
|-------|-------|
| Alvo | `helpers-02.deploy-01` |
| Decisão | exatamente uma: `GO` XOR `NO-GO` |
| Assinante | `Cappucceno` ou substituto GM formalmente indicado |
| Papel | `GM` ou papel equivalente de aprovação final |
| Data | ISO-8601 completa |
| Baseline | referência explícita a R208'/R211'/R213' |
| Se `GO` | janela, DRI executor e rollback owner |
| Se `NO-GO` | motivo objetivo e condição para novo request |

Ausência de qualquer campo mantém o deploy bloqueado e exige novo round documental,
sem criar `GO-SEC-002-helpers-02-deploy-01.md`.

---

## 4. Intake mínimo para D-3

Para abrir `SEC-002.helpers-03.apply-01.d3-sign-01.materialize-01`, a mensagem ou
artefato de autorização deve conter, no mínimo:

| Campo | Regra |
|-------|-------|
| Alvo | `helpers-03.apply-01` / decisão D-3 |
| Opção | exatamente uma: `D-3a` XOR `D-3b` XOR `D-3c` |
| Assinante | DRI Produto/Segurança ou substituto formalmente indicado |
| Papel | `DRI Produto/Segurança` ou equivalente |
| Data | ISO-8601 completa |
| Baseline | referência explícita a R209'/R210'/R212'/R214' |
| Efeito | reconhecer que `D-3a` ainda depende de helpers-02 deployado; `D-3b/D-3c` exigem bump |

Ausência de qualquer campo mantém D-3 bloqueada e preserva §5 de
`D-3-SEC-002.md` vazio.

---

## 5. Roteamento do próximo passo

Ao receber nova instrução:

1. Se contiver intake GM completo (§3), abrir apenas materialização documental GM.
2. Se contiver intake D-3 completo (§4), abrir apenas materialização documental D-3.
3. Se contiver ambos completos, preferir GM primeiro, porque `helpers-03` depende de
   helpers-02 deployado.
4. Se não contiver intake completo, continuar apenas com governança segura: status,
   checklist, guard, runbook ou preparação documental sem materialização.

Este roteamento impede que um “seguir” operacional seja confundido com assinatura
formal ou autorização de deploy.
