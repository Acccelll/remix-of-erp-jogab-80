# DB-006.slice-01 — Convenções de banco (prospectivas)

**Onda:** 7 · **Achado:** DB-006 · **Tipo:** STD · **Escopo:** ISOLADA (DevEx)

## Problema

Objetos do Postgres criados em três estilos convivem:
- Enums nativos (20) × `text+CHECK` (432).
- Funções em três padrões (`_privada`, `fn_`, livre; pt × en).
- Prefixação de tabela por domínio inconsistente.
- `trg_touch_updated_at` aplicado em parte das tabelas.

Sem regra escrita, novas migrations perpetuam o atrito.

## Alterações

**`docs/banco/convencoes.md`** (novo) — Guia único e prospectivo:
- Checklist rápido para PR de migration (8 itens).
- Nomenclatura por objeto (tabela/coluna/FK/índice/constraint/enum/função/trigger/view/mv) com exemplo pt-BR.
- Tabela de tipos canônicos (`uuid`/`timestamptz`/`numeric(14,2)`/`jsonb`, etc.).
- Bloco de segurança (ordem `CREATE → GRANT → ENABLE RLS → CREATE POLICY`) alinhado à regra global do projeto.
- Regras de migration e revisão de PR.
- Seção "Legado aceito" — objetos históricos não devem ser renomeados em massa.

Nenhuma migração retroativa. Nenhum código alterado.

## Validação

- `bunx tsgo --noEmit` sem impacto (documento puro).
- Critérios de aceite do achado atendidos:
  - (a) Guia publicado ✅
  - (b) Novas migrations devem aderir (regra de revisão explícita) ✅
  - (c) Exceções históricas registradas como legado aceito ✅
