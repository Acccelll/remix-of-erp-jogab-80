# OPS-004.slice-01 — Registry de saúde por fluxo (regra pura)

**Onda:** 7 · **Achado:** OPS-004 · **Tipo:** NEW · **Escopo:** LOTE (Plataforma)

## Problema

Falhas de fluxos críticos (importação TOTVS, sync de obra, fila
offline, filas de mobilização) só são notadas por reclamação. Não há
um lugar único que pergunte "todos os fluxos estão de pé?" nem um
`/health` agregado que um monitor externo possa consumir.

## Alterações

`src/lib/observability/flow-health.ts` (novo, `@module-kind pure`):
- `FlowHealthRegistry` com `register / noteOk / noteFail / snapshot /
  overallHealth / reset`.
- Definição de fluxo (`FlowDefinition`): `id`, `label`,
  `failThreshold` (default 3), `staleAfterMs` (default 30 min).
- Estado por fluxo (`FlowState`): `status`, `lastOkAt`, `lastFailAt`,
  `consecutiveFailures`, `lastError`.
- Regras de status:
  - `unknown` — nunca sinalizou.
  - `healthy` — último sinal foi OK.
  - `degraded` — falhas recentes < threshold.
  - `down` — falhas consecutivas ≥ threshold **ou** OK mais antigo
    que `staleAfterMs`.
- Agregado (`overallHealth`): `down` > `degraded` > `unknown` > `healthy`,
  com `healthy + unknown` → `degraded` (falta sinal em algum fluxo).
- Sem I/O, sem timers, sem `Date.now()` interno — consumidor injeta
  `now` (facilita monitores e testes determinísticos).
- Singleton `flowHealth` exportado para os call-sites reais.

`src/lib/observability/__tests__/flow-health.test.ts` (novo):
- 9 casos verdes cobrindo estado inicial, transição ok/fail,
  threshold, stale, agregação e no-op para id não registrado.

## Não escopo

- Não instrumenta os call-sites reais (fica para `slice-02`:
  TOTVS + sync + fila offline chamando `flowHealth.note*`).
- Não expõe `/health` HTTP (fica para `slice-03`: função pura
  `buildHealthPayload()` + endpoint edge/página `/health.json`).
- Não gera alertas persistentes — Sentry breadcrumbs continuam via
  `structured-logger` (OPS-003).

  (8 slice-01 OPS-003 + 6 slice-03 OPS-003 + 9 novos).
