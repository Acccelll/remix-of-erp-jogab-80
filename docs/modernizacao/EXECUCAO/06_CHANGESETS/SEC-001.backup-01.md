# SEC-001.backup-01 — Protocolo de backup lógico pré-migração

**Onda:** 2 (bloqueada — D-1/D-2 · cutover em pipeline dedicado)
**Data:** 2026-07-12
**Escopo:** apoio à Onda 2 autorizado por D-9. Define o backup obrigatório **antes** de aplicar `SEC-001.mig-01`. **Nenhum comando é executado neste changeset** — é o runbook aprovado que a operação de cutover seguirá.

## 1. Objetivo

Permitir rollback ponto-a-ponto de:

- `auth.users` (linhas com email `@planifik.local` ou `@obraflow.local`);
- `public.profiles`, `public.user_roles`, `public.user_empresas` (todas as linhas — volume baixo, dependência total do merge).

RTO alvo: < 15 min. RPO alvo: 0 (backup imediatamente antes do lock).

## 2. Pré-condições

1. `SEC-001.g` em produção (rotas cliente + edge function unificadas).
2. Janela de manutenção anunciada; login PHP↔Cloud pausado.
3. Operador com acesso ao `SUPABASE_DB_URL` (Lovable Cloud — via console de operação, nunca exposto em código).
4. Diretório destino cifrado e com retenção definida (§6).

## 3. Escopo do dump

Dois artefatos separados — o `auth.users` requer permissões elevadas e é tratado em arquivo próprio.

### 3.1 Artefato A — tabelas `public`

```bash
pg_dump \
  --format=custom \
  --no-owner --no-privileges \
  --data-only \
  --table=public.profiles \
  --table=public.user_roles \
  --table=public.user_empresas \
  --file="sec001_public_${STAMP}.dump" \
  "$SUPABASE_DB_URL"
```

### 3.2 Artefato B — recorte de `auth.users`

```bash
psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 -c "
  COPY (
    SELECT id, email, created_at, updated_at, raw_user_meta_data
    FROM auth.users
    WHERE email LIKE '%@planifik.local'
       OR email LIKE '%@obraflow.local'
  ) TO STDOUT WITH (FORMAT csv, HEADER true)
" > "sec001_auth_users_${STAMP}.csv"
```

CSV (não `pg_dump`) porque escrever direto em `auth.users` no restore exige `UPDATE`/`INSERT` manual com verificação — nunca `pg_restore` cego no schema `auth`.

## 4. Verificação de integridade do backup

```bash
# 4.1 Contagem de linhas do CSV bate com o banco
BANK=$(psql "$SUPABASE_DB_URL" -tAc "
  SELECT count(*) FROM auth.users
  WHERE email LIKE '%@planifik.local' OR email LIKE '%@obraflow.local'
")
CSV=$(($(wc -l < "sec001_auth_users_${STAMP}.csv") - 1))
test "$BANK" = "$CSV" || { echo "MISMATCH auth: $BANK vs $CSV"; exit 1; }

# 4.2 Dump public restaurável
pg_restore --list "sec001_public_${STAMP}.dump" | grep -E 'profiles|user_roles|user_empresas'

# 4.3 Hash de integridade
sha256sum sec001_public_${STAMP}.dump sec001_auth_users_${STAMP}.csv > "sec001_${STAMP}.sha256"
```

Só prosseguir para `SEC-001.mig-01` se as três verificações passarem.

## 5. Ordem cronológica no cutover

```
T-15min  anúncio + freeze de logins
T-5min   §3.1 + §3.2 + §4 (backup + verify)
T=0      SEC-001.mig-01 §1 locks
T+..     SEC-001.mig-01 §3..§6 execução
T+verif  SEC-001.mig-01 §7 checks (todos devem retornar 0)
T+ok     unfreeze
T+fail   §7 do runbook — rollback
```

## 6. Retenção

- Cifrar com `age` ou `gpg` (chave do operador GM).
- Reter **30 dias** offline em bucket de operação; **não** subir para storage do próprio projeto.
- Excluir após 30 dias com log auditável.

## 7. Rollback (uso do backup)

Somente se `SEC-001.mig-01 §7` reportar divergência:

1. **Reverter deploy** de `SEC-001.g` (bloqueia novas duplicatas).
2. **Restaurar `public`** (dump é `--data-only`; TRUNCATE antes):
   ```bash
   psql "$SUPABASE_DB_URL" -c "
     TRUNCATE public.user_empresas, public.user_roles, public.profiles RESTART IDENTITY;
   "
   pg_restore --data-only --disable-triggers \
     --dbname="$SUPABASE_DB_URL" \
     "sec001_public_${STAMP}.dump"
   ```
3. **Restaurar `auth.users`** — merge manual a partir do CSV:
   - `UPDATE auth.users SET email = csv.email WHERE id = csv.id;`
   - `INSERT ... ON CONFLICT (id) DO NOTHING` para linhas removidas em §5 do mig-01.
4. Rodar as três queries de `SEC-001.mig-01 §7` — todas devem voltar a bater com o pré-estado.

## 8. Riscos conhecidos

- `raw_user_meta_data` pode conter chaves adicionadas por `handle_new_user` entre o dump e o restore — sobrescrita é aceitável dentro da janela de freeze.
- Refresh tokens ativos são invalidados no restore de `auth.users`; usuários precisarão relogar (esperado no cutover).
- Se surgir nova FK a `auth.users` não listada em `SEC-001.mig-01 §2`, abortar e reemitir o mig-01.

## 9. Fora de escopo

- Execução do backup — só na janela de cutover.
- Automação em pipeline CI — fica em `OPS-*` futuro (não bloqueia Onda 2).
- Backup completo do projeto — responsabilidade da plataforma; este runbook é o recorte cirúrgico da migração.

## 10. Impacto em produção

**Nenhum.** Apenas runbook. Nenhum comando foi executado; nenhum arquivo em `src/`, `supabase/migrations/` ou `supabase/functions/` foi criado ou alterado.
