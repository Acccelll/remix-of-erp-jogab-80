# OPS-004 — NOTA-FIM · Monitor de fluxos críticos + payload de health

**Onda:** 07 · Observabilidade
**Achado:** OPS-004 — "Sem monitor por fluxo crítico e sem `/health` agregado".
**Status:** entregue (slices 01–03). Handoff parcial para plataforma.

## Consolidado das slices

### `slice-01` — Registry puro
- `src/lib/observability/flow-health.ts` (`@module-kind pure`): `FlowHealthRegistry` com `register / noteOk / noteFail / snapshot / overallHealth / reset`.
- Regras: `unknown → healthy → degraded → down` (por threshold de falhas consecutivas **ou** staleness).
- Agregação hierárquica: `down > degraded > unknown > healthy`; `healthy + unknown` puxa para `degraded`.
- Sem I/O, sem `Date.now()` — consumidor injeta `now`.
- Singleton `flowHealth` exportado.
- 9 testes verdes.

### `slice-02` — Instrumentação de call-sites reais
- `src/lib/observability/critical-flows.ts` (`@module-kind orchestration`): IDs estáveis (`totvs.import`, `obra.sync`, `offline.queue`) + `registerCriticalFlows`, `noteCriticalFlowOk/Fail`, wrapper `observeCriticalFlow(id, fn)`.
- Registro executado a partir de `installObservabilitySinks()` (bootstrap).
- Call-sites reais chamando os helpers; cada marcação também emite evento estruturado (`flow.health.ok` / `flow.health.fail`) via `structured`.
- 3 testes verdes.

### `slice-03` — Payload agregado + superfície de monitor
- `src/lib/observability/health-report.ts` (`@module-kind pure`): `buildHealthReport(now, registry?)` → `HealthReport { schemaVersion: 1, generatedAt, status, flows[], summary }`. Timestamps ISO-8601, `null` para ausentes (JSON-safe). `healthReportHttpStatus` → `200 | 207 | 503`.
- Bootstrap expõe `window.__planifikHealth()` e `window.__planifikHealthHttpStatus()` (leitura sob demanda).
- 4 testes verdes.
