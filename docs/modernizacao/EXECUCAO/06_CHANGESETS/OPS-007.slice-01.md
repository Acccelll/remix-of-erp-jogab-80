# OPS-007.slice-01 — Runbooks operacionais iniciais

**Onda:** 7 · **Achado:** OPS-007 · **Tipo:** DOC · **Escopo:** LOTE
(Plataforma) · **Dependências:** OPS-001, OPS-006 (satisfeitas).

## Problema

Onda 07 exige documentação operacional viva. Não existia um índice
de runbooks nem procedimentos escritos para os incidentes mais
prováveis (edge function 5xx, import travado, notificação parada,
RLS negando leitura, perda de sessão). On-call ficava dependente do
conhecimento tácito.

## Alterações

Nova pasta `docs/runbooks/` com:

- `README.md` — índice, convenções (severidades S1-S4, canais,
  cadência de revisão) e governança.
- `rb-01-edge-function-erro.md` — 5xx em `/functions/*`.
- `rb-02-import-totvs-bms.md` — import TOTVS/BMS travado.
- `rb-03-notificacoes.md` — fila de notificações parada.
- `rb-04-rls-permission-denied.md` — RLS negando leitura legítima.
- `rb-05-perda-sessao.md` — perda de sessão em massa (S1).

Cada runbook segue o padrão fixo **Sintoma → Diagnóstico → Ação →
Verificação → Pós-incidente + Histórico**.

## Não escopo

- Não substitui monitoramento agregado (OPS-004) nem logging
  estruturado (OPS-003) — aponta para eles quando aplicável.
- Não gera automação: runbooks são humanos, executados por on-call.
- Runbooks especulativos (para incidentes ainda não observados) só
  entram após a primeira ocorrência, conforme regra em `README`.

## Validação

- Sem código; apenas documentação.
- Todos os links relativos apontam para arquivos existentes
  (`docs/operacao/ambientes.md`, achados da Onda 07).

## Estado

**OPS-007 encerrado** com o conjunto mínimo viável de runbooks.
Ampliações futuras (novos incidentes reais) devem seguir o mesmo
template e serem indexadas em `docs/runbooks/README.md`.
