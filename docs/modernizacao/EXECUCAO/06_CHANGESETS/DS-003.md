# DS-003 — Fonte única de confirmação (sem `window.confirm`)

**Onda:** 4 — Padronização  
**Data:** 2026-07-11  
**Tipo:** STD  
**Escopo:** consolidação transversal de diálogos de confirmação.

## Antes

- 10 call-sites em 10 arquivos usavam `window.confirm` nativo, com UI destoante do sistema de design, sem foco acessível padronizado e sem suporte a variantes destrutivas.
- Estilos e labels ("Excluir?/Remover?") eram redigidos ad-hoc a cada uso.

## Depois

- Novo módulo `src/lib/ui/confirm.tsx` expõe:
  - `confirmDialog(opts): Promise<boolean>` — API imperativa promise-based;
  - `<ConfirmDialogHost />` — host único, montado uma vez em `src/App.tsx`, que renderiza `AlertDialog` do design system;
  - suporte a `variant: "destructive" | "default"`, `title`, `description`, `confirmLabel`, `cancelLabel`;
  - fallback defensivo para `window.confirm` apenas se o host não estiver montado (ex.: testes sem provider).
- Todos os 10 call-sites migrados: os handlers passaram a `async` onde necessário e chamam `await confirmDialog(...)`.

## Arquivos migrados

- `src/pages/GM.tsx`
- `src/pages/InspecoesQR.tsx`
- `src/pages/InspecoesAgenda.tsx`
- `src/pages/GMFeatureFlags.tsx`
- `src/pages/admin/Empresas.tsx`
- `src/pages/planejamento/LicoesAprendidas.tsx`
- `src/pages/planejamento/Riscos.tsx`
- `src/pages/suprimentos/GruposNegociacao.tsx`
- `src/pages/financeiro/FinCentros.tsx`
- `src/components/obra/LinhaBalancoTab.tsx`

## Validação

- `rg -n "\bconfirm\(" src` retorna apenas 1 ocorrência: o fallback interno do próprio `src/lib/ui/confirm.tsx`.
- `bunx tsgo --noEmit` verde.

## Risco e rollback

- Risco baixo: mudança de UI/UX de confirmação, mesma semântica de fluxo (aprova/cancela).
- Rollback: remover import + reverter cada `await confirmDialog(...)` para `confirm(...)`. Host pode permanecer montado sem efeito.
