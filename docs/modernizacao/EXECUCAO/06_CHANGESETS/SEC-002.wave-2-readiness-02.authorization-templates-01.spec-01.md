## 1. Objetivo

Especificar os templates canônicos que uma autorização futura deve seguir para
destravar, separadamente, os dois bloqueios externos remanescentes da Onda 2:

1. GO/NO-GO GM para `helpers-02.deploy-01`.
2. Decisão D-3 para `helpers-03.apply-01`.

Este changeset **não cria** `GO-SEC-002-helpers-02-deploy-01.md`, **não preenche**
§5 de `D-3-SEC-002.md`, **não assina**, **não publica função**, **não gera SQL** e
**não aplica** nenhuma alteração operacional. Ele apenas fixa os modelos textuais
que um futuro round de materialização deverá preencher se receber intake válido
conforme R216'.

## 4. Regras de uso dos templates

1. Templates são **contratos de formato**, não autorizações.
2. Um template copiado sem decisão/opção única, papel, data ISO-8601 e hash baseline
   não produz efeito.
3. Um futuro round pode materializar GM ou D-3, mas não deve combinar assinatura e
   deploy/apply no mesmo changeset.
4. Se ambos os intakes chegarem completos, a ordem recomendada permanece: GM → deploy
   helpers-02 → D-3 → apply helpers-03.
5. Qualquer divergência entre template e R213'/R214' deve ser resolvida por nova spec
   antes de materialização.
