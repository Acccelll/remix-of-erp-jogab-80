## 1. Objetivo

Preparar e formalizar o **pacote de autorização GM** para o deploy de `helpers-02`
(edge function set responsável pelo pipeline `tests-02` server-side), **sem executar
nenhuma ação de deploy**. Este spec descreve exclusivamente o conteúdo do request
que será submetido ao GM (`Cappucceno`) e o critério objetivo de aprovação/negação.

Após assinatura GM (GO / NO-GO), abre-se `SEC-002.helpers-02.deploy-01.materialize-01`
(materialização do deploy) — que **permanece bloqueado** até a assinatura chegar.

O request formaliza ao GM:

- **Artefatos alvo do deploy** (referenciados por caminho, não anexados):
  - `supabase/functions/sec002-helpers-02/*` (código já congelado em R183)
  - manifest `helpers-02` já validado por PC6 (verifier)
- **Ambiente alvo:** produção (`main`)
- **Janela:** a definir pelo GM na assinatura
- **Rollback:** documentado inline (remoção da função + revert do manifest;
  banco intocado — helpers-02 não altera schema)
- **Blast radius:** nulo em leitura; escrita apenas em tabelas já cobertas
  por RLS + policies R132; sem acesso a `auth`/`storage`/`vault`
- **Dependências externas:** nenhuma (D-3 é bloqueio de `helpers-03`, não de `helpers-02`)
