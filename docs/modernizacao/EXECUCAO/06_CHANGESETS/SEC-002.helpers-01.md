# SEC-002.helpers-01 — Spec das funções de autorização RLS

**Onda:** 2 (preparatória — bloqueada por fechamento de `SEC-001`)
**Data:** 2026-07-12
**Escopo:** especifica as **quatro funções `security definer`** que sustentam as regras-alvo dos lotes C (obras), D (dp/financeiro) e E (boards/cards) do plano `SEC-002`. Este changeset é **apenas especificação**: nenhuma migração é aplicada, nenhum código de produção é alterado. O SQL abaixo é a forma canônica que a migração `SEC-002.helpers-02.migration` executará, sob gate, quando o release train `SEC-001` estiver encerrado.

## 1. Motivação

`SEC-002.inventory-02` mostrou 96 políticas `auth-only` e 184 `permissive-authenticated` que precisam migrar para regras de negócio explícitas por **empresa**, **obra**, **board** ou **card**. Reimplementar essa lógica inline em cada policy é:

- **repetitivo** — 73 tabelas, 4 comandos cada;
- **inseguro** — join/subselect em RLS pode causar recursão infinita;
- **caro** — planner recomputa a mesma condição por linha.

A convenção do projeto (`has_role`, `current_is_gm`) já isola esse padrão em funções `security definer`. Este changeset estende a convenção.

## 2. Contrato compartilhado

Todas as funções deste changeset obedecem simultaneamente:

- `language sql`
- `stable`
- `security definer`
- `set search_path = public`
- **entrada:** `_user uuid` primeiro, depois `_alvo uuid`
- **saída:** `boolean` — `true` se `_user` tem vínculo, `false` caso contrário
- **NULL-safety:** retorno `false` quando qualquer argumento é `NULL` (evita false positives em joins)
- **owner do objeto:** `postgres` (default de migração), grants `execute` para `authenticated` e `service_role`, revoke `execute` de `anon` e `public`

Nome do bloco de grants padrão (aplicado a cada função):

```sql
revoke all on function public.<fn>(uuid, uuid) from public, anon;
grant execute on function public.<fn>(uuid, uuid) to authenticated, service_role;
```

## 4. Funções

### 4.1 `public.user_in_empresa(_user uuid, _empresa uuid) returns boolean`

```sql
create or replace function public.user_in_empresa(_user uuid, _empresa uuid)
returns boolean
language sql
stable
security definer
set search_path = public
as $$
  select exists (
    select 1 from public.user_empresas ue
    where ue.user_id = _user and ue.empresa_id = _empresa
  ) or public.current_is_gm();
$$;
```

- **Regra:** membro direto da empresa **ou** GM.
- **Uso:** lotes C (obras, colaboradores, patrimonios, veiculos, responsabilidades_patrimonios) e B (empresas, user_empresas).
- **Índice de suporte:** `create index if not exists idx_user_empresas_user_empresa on public.user_empresas(user_id, empresa_id);` — objeto separado, entra na migração `SEC-002.helpers-02.migration`.

### 4.2 `public.user_in_obra(_user uuid, _obra uuid) returns boolean`

```sql
create or replace function public.user_in_obra(_user uuid, _obra uuid)
returns boolean
language sql
stable
security definer
set search_path = public
as $$
  select
    public.current_is_gm()
    or exists (
      select 1 from public.obra_membros om
      where om.user_id = _user and om.obra_id = _obra
    )
    or exists (
      select 1 from public.obras o
      join public.user_empresas ue on ue.empresa_id = o.empresa_id
      where o.id = _obra and ue.user_id = _user
    );
$$;
```

- **Regra:** GM **ou** membro direto da obra **ou** membro da empresa dona da obra.
- **Justificativa do fallback empresa:** hoje `obra_membros` não é populado para toda obra; enquanto isso não fecha, o vínculo por empresa mantém compatibilidade sem abrir escopo.
- **Índices de suporte:** `create index if not exists idx_obra_membros_user_obra on public.obra_membros(user_id, obra_id);` — `obras(empresa_id)` já tem cobertura via FK padrão; verificar no gate.

### 4.3 `public.user_in_board(_user uuid, _board uuid) returns boolean`

```sql
create or replace function public.user_in_board(_user uuid, _board uuid)
returns boolean
language sql
stable
security definer
set search_path = public
as $$
  select
    public.current_is_gm()
    or exists (
      select 1 from public.boards b
      where b.id = _board and b.owner_id = _user
    )
    or exists (
      select 1 from public.board_membros bm
      where bm.board_id = _board and bm.user_id = _user
    )
    or exists (
      select 1 from public.boards b
      where b.id = _board
        and b.obra_id is not null
        and public.user_in_obra(_user, b.obra_id)
    );
$$;
```

- **Regra:** GM **ou** owner do board **ou** membro do board **ou** membro da obra do board (quando o board é vinculado a obra).
- **Recursão:** chama `user_in_obra`, que **não** chama `user_in_board`. Sem ciclo.
- **Índice de suporte:** `create index if not exists idx_board_membros_board_user on public.board_membros(board_id, user_id);`.

### 4.4 `public.user_in_card(_user uuid, _card uuid) returns boolean`

```sql
create or replace function public.user_in_card(_user uuid, _card uuid)
returns boolean
language sql
stable
security definer
set search_path = public
as $$
  select
    public.current_is_gm()
    or exists (
      select 1 from public.cards c
      where c.id = _card and c.responsavel_id = _user
    )
    or exists (
      select 1 from public.card_membros cm
      where cm.card_id = _card and cm.user_id = _user
    )
    or exists (
      select 1 from public.card_board_posicao p
      where p.card_id = _card
        and public.user_in_board(_user, p.board_id)
    )
    or exists (
      select 1 from public.cards c
      where c.id = _card
        and c.obra_id is not null
        and public.user_in_obra(_user, c.obra_id)
    );
$$;
```

- **Regra:** GM **ou** responsável direto **ou** membro do card **ou** membro de qualquer board onde o card aparece **ou** membro da obra do card.
- **Recursão:** chama `user_in_board` e `user_in_obra`, nenhuma delas chama `user_in_card`. Sem ciclo.
- **Índice de suporte:** `create index if not exists idx_card_membros_card_user on public.card_membros(card_id, user_id);` + `create index if not exists idx_card_board_posicao_card_board on public.card_board_posicao(card_id, board_id);`.

## 5. Invariantes

- **I-H1.** Nenhuma função lê tabela sem `security definer` — impede loop RLS.
- **I-H2.** `current_is_gm()` sempre é a primeira alternativa avaliada — curto-circuito para o caminho mais quente.
- **I-H3.** Toda função retorna `false` para `NULL` em qualquer argumento (comportamento natural de `=` com `NULL`; nenhum `coalesce` é introduzido).
- **I-H4.** `execute` é concedido apenas a `authenticated` e `service_role`. `anon` nunca.
- **I-H5.** Nenhuma função escreve — todas são `stable`.
- **I-H6.** Ordem topológica de chamadas: `user_in_empresa` → (folha); `user_in_obra` → `user_in_empresa` (indireto via join); `user_in_board` → `user_in_obra`; `user_in_card` → `user_in_board`, `user_in_obra`. DAG sem ciclos.

## 7. Migração (não executada aqui)

O bloco `SEC-002.helpers-02.migration` conterá, na ordem:

1. `create or replace function` — as quatro funções em §4.
2. `revoke ... grant ...` — bloco de §2 aplicado a cada uma.
3. `create index if not exists` — os quatro índices citados em §4.
4. `comment on function` — resumo de regra + link para este changeset.

Idempotente, reentrant, sem `drop`.

## 8. Riscos e mitigação

- **R1: performance de `user_in_card` em telas de listagem.** Mitigação: índices §4.4 + policy `select` sobre `cards` faz o filtro antes do join.
- **R2: divergência de nome de coluna.** Mitigação: §3 documenta as colunas verificadas hoje; qualquer renome quebra o gate de migração.
- **R3: `current_is_gm` inexistente ou incorreta em ambientes antigos.** Pré-requisito: `SEC-001.k` conclui a canonicalização de `current_is_gm`.
- **R4: policy que ainda usa `USING (true)` mascara falha de helper.** Só se manifesta durante o Lote B/C/D/E, não aqui.

## 9. Impacto em produção

**Nenhum.** Documento de especificação. Nenhuma função criada, nenhum grant emitido, nenhum código do frontend alterado.
