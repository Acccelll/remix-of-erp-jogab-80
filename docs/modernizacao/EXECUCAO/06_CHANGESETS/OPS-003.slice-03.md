# OPS-003.slice-03 — Propagação de X-Correlation-Id ao Supabase / Edge

**Onda:** 7 · **Achado:** OPS-003 · **Tipo:** STD/REF · **Escopo:** LOTE (Plataforma)

## Problema

O cliente `supabase-js` é gerado automaticamente (`src/integrations/supabase/client.ts`,
não editável) e não propaga `X-Correlation-Id`. Chamadas ao PostgREST,
Auth e Edge Functions ficavam fora da trilha de correlação criada nos
slices 01/02 — o id só chegava no PHP.

## Alterações

`src/lib/observability/fetch-interceptor.ts` (novo, `@module-kind io`):
- `installFetchInterceptor({ matchHosts?, matchPathIncludes? })` faz
  monkey-patch idempotente em `globalThis.fetch`.
- Alvos padrão: host de `VITE_SUPABASE_URL` + qualquer path que inclua
  `/functions/v1/`.
- Para requisições alvo:
  - Injeta header `X-Correlation-Id` (contexto `getCorrelationId()`
    quando existir, senão `newCorrelationId("sb")`), sem sobrepor
    quando o caller já enviou o header.
  - Emite `sb.fetch.ok` | `sb.fetch.http_error` | `sb.fetch.fail` com
    `url`, `status`, `durationMs` e `error`.
- Requisições fora do alvo passam pelo `originalFetch` intactas
  (sem header, sem evento) — evita ruído em CDN, assets, terceiros.
- Preserva a interface de `fetch` (aceita `string | URL | Request`).

`src/lib/observability/bootstrap.ts`:
- `installObservabilitySinks()` agora também chama
  `installFetchInterceptor()` na sequência. Continua idempotente.

`src/lib/observability/__tests__/fetch-interceptor.test.ts` (novo):
- 6 casos verdes: propaga contexto, ignora fora do alvo, gera id
  efêmero sem contexto, emite `http_error` em 5xx, emite `fail` em
  falha de rede e propaga a exceção, instalação idempotente.

## Não escopo

- Não edita `src/integrations/supabase/client.ts` (auto-gerado).
- Não altera comportamento do backend (leitura do header no PHP /
  edges fica para o backend team; o header já chega hoje).
- Não introduz `invokeEdge` helper — se necessário vira slice-04.
- Não instrumenta React Query / repositórios diretamente (o evento
  vem naturalmente do `fetch`).

## Validação

- `bunx tsgo --noEmit` limpo.
- `bunx vitest run src/lib/observability` → **14/14 verde**
  (8 do slice-01 + 6 do slice-03).
- Teste manual no DevTools > Network: qualquer request ao domínio
  Supabase ou a `/functions/v1/*` carrega `X-Correlation-Id`.
