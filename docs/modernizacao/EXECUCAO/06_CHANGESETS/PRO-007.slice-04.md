# PRO-007.slice-04 — Repositório de NCs com mapper do workflow

**Onda:** 07 · `PRO-007`  
**Achado-base:** PRO-007 — "NC sem workflow ativo (sem responsável/prazo/reinspeção/notificação)".  
**Dependências satisfeitas:** `slice-01` (FSM), `slice-02` (mapper), `slice-03` (schema).  
**Escopo desta fatia:** camada de repositório. Sem alteração visual em `NaoConformidades.tsx` e sem gatilhos novos de notificação.

## Problema

Com a FSM e as colunas já prontas, ainda faltava um ponto único para persistir o workflow sem espalhar regras pela UI. A página legada continua falando em `quem`, `quando_planejado`, `como` e `aguardando_verificacao`; o workflow novo fala em `responsavel_id`, `prazo`, `tratativa` e `aguardando_reinspecao`.

## Entrega

1. **`src/lib/repositories/inspecoes.ts`**
   - `NC_WORKFLOW_SELECT` fixa a projeção mínima para reidratar a FSM.
   - `ncWorkflowFromRow(row)` adapta linhas novas e legadas para `NCState`.
   - `naoConformidadesRepo.update()` passa a enriquecer patches legados:
     - `quem` → `responsavel_id`
     - `quando_planejado` → `prazo`
     - `como` / `acao_corretiva` → `tratativa`
     - `aguardando_verificacao` → `status='em_tratativa'` + `aguardando_reinspecao=true`
   - Novos métodos de workflow:
     - `getWorkflowState(id)`
     - `setWorkflowState(id, state)`
     - `updateWorkflowState(id, before, after)` usando `diffRow`
     - `applyTransition(id, event)` usando `transition`
   - Persistência espelhada para manter compatibilidade com a UI atual até o slice de interface.

2. **`src/lib/__tests__/integracao/repositories-contrato-k.test.ts`**
   - Teste de compatibilidade do `update()` legado.
   - Teste de reidratação do workflow a partir de campos novos/legados.
   - Teste de `applyTransition()` garantindo diff mínimo espelhado.

## Decisão técnica

O repositório mantém ambos os contratos por enquanto. Isso evita quebrar a tela existente antes do `slice-05` e permite que a UI migre de forma incremental para a FSM.
