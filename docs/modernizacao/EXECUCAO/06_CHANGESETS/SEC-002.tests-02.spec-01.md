## 2. Esqueleto canônico por arquivo

```sql
-- test_id: SEC-002.T-<lote>-<tabela>-<caso>
begin;
select plan(4);  -- SELECT, INSERT, UPDATE, DELETE
\i _lib/fixtures.sql
\i _lib/jwt.sql
\i _lib/assert.sql

select pg_temp.set_jwt_<caso>();  -- helper de perfil

-- oráculo por comando (4 asserts)
select pg_temp.assert_rls_select('<tabela>', '<expect>');
select pg_temp.assert_rls_insert('<tabela>', '<expect>');
select pg_temp.assert_rls_update('<tabela>', '<expect>');
select pg_temp.assert_rls_delete('<tabela>', '<expect>');

select * from finish();
rollback;
```

`<expect>` ∈ `{allow, deny, empty}`. `empty` = SELECT retorna 0 linhas; `deny` = comando levanta `permission denied` ou `new row violates row-level security`.

## 5. Gerador determinístico

Script `scripts/sec002/gen-tests-02.mjs` (a criar em R186) lê `SEC-002.inventory-02.csv` e emite os 315 arquivos aplicando o esqueleto §2 + oráculo §4. Regras:

2. Determinístico: sem timestamp, sem UUID novo, ordering alfabético por `<tabela>__<caso>.sql`.
3. Gate: `node gen-tests-02.mjs --check` retorna exit 1 se qualquer arquivo divergir do esperado.
4. Nunca sobrescreve arquivos em `_lib/`, `helpers/`, `batch-*/` já existentes fora do padrão `<tabela>__<caso>.sql`.
