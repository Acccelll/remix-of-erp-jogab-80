# OPS-005.slice-03 — Superfície diagnóstica do coletor externo

**Onda:** 07 · Observabilidade
**Achado-base:** OPS-005 — "Sem coletor externo de eventos estruturados; volume alto sem estratégia de amostragem".
**Escopo desta fatia:** expor estado operacional do sink externo (buffer, backoff, últimas flushes) para monitoração local e para o coletor de suporte.

## Problema
O sink instalado em `slice-02` opera de forma silenciosa: sem visibilidade de fila, drops, falhas de rede ou backoff em curso, ficamos cegos em incidentes ("está tudo enviando?", "quantos eventos ficaram para trás?").

## Entrega
1. **`event-buffer.ts`** — adiciona `getCapacity()` para reportar o teto do buffer sem quebrar encapsulamento.
2. **`event-collector.ts`**
   - Novo tipo `ExternalCollectorDiagnostics` (`schemaVersion: 1`).
   - `ExternalEventSink.diagnostics()` cumulativo: `bufferSize / bufferCapacity`, `droppedTotal`, `inFlight`, `failures`, `backoffUntil` + `backoffRemainingMs`, e last flush (`at`, `reason`, `ok`, `error`, `events`) além de `totalFlushes` / `totalEventsSent`.
   - `getExternalCollectorDiagnostics()` no módulo — retorna `null` quando o sink não está instalado (endpoint ausente).
   - `flush()` e `flushBeacon()` passam a preencher os campos de diagnóstico (inclusive `lastFlushError` textual).
3. **`bootstrap.ts`** — expõe `window.__planifikCollector()` ao lado de `__planifikHealth`, para ferramentas de suporte inspecionarem via console.
4. **Testes novos** — `collector-diagnostics.test.ts` (4 casos): estado inicial, flush ok, flush com falha + backoff + requeue, contagem cumulativa de drops por overflow.

- UI operacional (plano Onda 08).
- Envio periódico do diagnóstico para o coletor externo (evita loop com o próprio transporte).
- Redação/mascaramento do `endpoint` — hoje devolvido íntegro, pois é interno.
