# DB-001.b — Plano FK real + gate de regressão

**Onda:** 3  
**Achado:** DB-001 (Lote B)  
**Status:** concluído

## Contexto

DB-001.a garantiu formato e detecção de órfãos na fronteira PHP↔Supabase. Faltava (i) o plano faseado de conversão para FK real e (ii) um gate de CI que impeça regressão.

## Mudanças

- **Plano faseado** documentado em `docs/modernizacao/EXECUCAO/03_IMPLEMENTACAO/DB-001_Plano_FK_Real.md`, com 4 fases (colaboradores, patrimonios, veiculos, obras) e critérios objetivos por changeset `DB-001.c.<n>`.
- **Gate de regressão** `scripts/verify-db001-orfaos.sh`:
  - Consulta `public.vw_db001_fronteira_orfaos` via `psql`.
  - Falha (`exit 1`) se `SUM(total_orfaos) > 0`.
  - Sem `DATABASE_URL`, encerra como `skipped` (não bloqueia PRs de fork).
- **CI**: novo passo _Verify DB-001 fronteira sem órfãos_ em `.github/workflows/ci.yml` após BIZ-002, usando `secrets.DATABASE_URL_READONLY`.
- **package.json**: novo script `verify:db001-orfaos`.

## Validação

- `bash scripts/verify-db001-orfaos.sh` local: retorna `skipped` (sem DATABASE_URL) com exit 0.
- Fluxo do gate revisado: quando conectado, a view retornou `total_orfaos=0` na aplicação de DB-001.a.

## Critérios DB-001

- (a) Inventário/CHECK de formato ✅ (DB-001.a)
- (b) Rotina de detecção zerada ✅ (DB-001.a)
- (c) Plano de conversão para FK real ✅ (este changeset) — execução por fase acompanha migração canônica das entidades.
- (d) Gate de regressão em CI ✅ (este changeset).
