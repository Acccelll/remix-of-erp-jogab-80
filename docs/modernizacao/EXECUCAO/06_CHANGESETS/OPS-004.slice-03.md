# OPS-004.slice-03 — Payload agregado de health + superfície de monitor externo

**Onda:** 07 · Observabilidade
**Achado-base:** OPS-004
**Escopo desta fatia:** camada de saída do health registry.

## Problema
`FlowHealthRegistry` (slice-01) e call-sites instrumentados (slice-02) já produzem sinais, mas não havia um **payload estável e serializável** para monitor externo, `/health` ou inspeção manual em produção.

## Entrega
1. **`src/lib/observability/health-report.ts`** (`@module-kind pure`)
   - `buildHealthReport(now, registry?)` → `HealthReport { schemaVersion: 1, generatedAt, status, flows[], summary }`.
   - `HealthFlowEntry` normaliza timestamps para ISO-8601 e `lastError`/timestamps ausentes viram `null` (JSON-safe).
   - `summary` agrega contagem por status (`unknown|healthy|degraded|down`).
   - `healthReportHttpStatus(report)` → `200 | 207 | 503` para `/health` externo:
     - `healthy` → 200
     - `degraded` / `unknown` → 207 (parcial)
     - `down` → 503
2. **`bootstrap.ts`** — `installHealthSurface()` expõe `window.__planifikHealth()` e `window.__planifikHealthHttpStatus()` (leitura sob demanda, sem timer). Idempotente via guard já existente de `installObservabilitySinks()`.
3. **Testes** (`__tests__/health-report.test.ts`) — 4 cenários: schema estável / unknown, serialização ISO + lastError, threshold → down, mapeamento HTTP.

## Validação
- `bunx vitest run src/lib/observability` → **30/30 verdes** (9 flow-health + 4 health-report + 8 structured-logger + 3 critical-flows + 6 fetch-interceptor).
- `bunx tsgo --noEmit` limpo.
- DevTools: `window.__planifikHealth()` retorna payload; `window.__planifikHealthHttpStatus()` retorna código HTTP correspondente.

## Fora de escopo
- Endpoint HTTP `/health` real (depende de backend PHP/edge — próximo passo do time de plataforma).
- Push periódico para coletor externo (OPS-005).
- UI operacional consumindo o payload (será um card em Onda 08).
