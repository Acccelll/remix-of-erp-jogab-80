# ARC-003.d — Gate de fronteira de repositories

**Onda:** 3  
**Achado:** ARC-003 (Lote D)  
**Status:** concluído

## Contexto

Lotes A–C do ARC-003 migraram todos os domínios ativos para `src/lib/repositories/*`, mas nada impedia que uma alteração futura em `pages/` ou `components/` reintroduzisse `supabase.from("<tabela coberta>")`. Duas regressões foram encontradas na auditoria: `FinObras.tsx` e `FinFluxo.tsx` acessavam `clientes` diretamente.

## Mudanças

- `src/pages/financeiro/FinObras.tsx` — passa a usar `clientesRepo.list()`.
- `src/pages/financeiro/FinFluxo.tsx` — passa a usar `clientesRepo.listIdNome()`.
- Novo `scripts/verify-repository-boundary.sh` — lista de tabelas cobertas + arquivo de exceções (`src/lib/cards/trello-import.ts`); falha com exit 1 se encontrar bypass.
- `.github/workflows/ci.yml` — novo passo _Verify repository boundary (ARC-003.d)_ após BIZ-002.
- `package.json` — script `verify:repo-boundary`.

## Validação

- `bash scripts/verify-repository-boundary.sh` → OK, 0 bypasses.
- Auditoria final: `rg supabase.from(...)` em `pages/`+`components/` restringe-se a tabelas **não cobertas** por repository (cronograma_baselines/dependencias/revisoes, inspecao_qr_alvos/agendas, boards, notas_fiscais, recebimentos, etc.). Cada nova tabela ganha entrada em `COVERED_TABLES` quando seu repository nascer.

## Critérios ARC-003

- (a–c) migração por lotes ✅ (A/B/C)
- (d) gate de regressão em CI ✅ (este changeset)

## Próximo

Ampliar `COVERED_TABLES` conforme novos repositories forem criados (ex.: `boards`, `notas_fiscais`, `recebimentos` completos, cronograma auxiliar).
