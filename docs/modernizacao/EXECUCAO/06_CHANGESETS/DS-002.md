# DS-002 — Sistema único de toast

**Onda:** 4 — Padronização  
**Data:** 2026-07-11  
**Tipo:** STD  
**Escopo:** consolidação transversal de notificações.

## Antes

- O app montava dois providers de toast no `App`.
- Havia chamadas via `sonner` e via `useToast`/Radix, gerando dois comportamentos visuais e APIs distintas.

## Depois

- `sonner` passa a ser o único sistema ativo de notificações.
- O provider Radix/shadcn foi removido da raiz da aplicação.
- As chamadas remanescentes de `useToast` foram migradas para `toast.success`/`toast.error` do `sonner`.
- Os arquivos do sistema legado de toast foram removidos para impedir novos usos acidentais.

## Validação

- `rg "@/hooks/use-toast|components/ui/use-toast|components/ui/toaster|components/ui/toast|useToast|<Toaster" src` deve retornar zero ocorrências.
- O único provider de notificação deve permanecer `src/components/ui/sonner.tsx` montado em `src/App.tsx`.

## Risco e rollback

- Risco baixo: alteração de API visual, sem mudança de regra de negócio.
- Rollback: restaurar os arquivos removidos e remontar o provider antigo no `App`, caso alguma chamada legada não mapeada seja identificada.
