# TST-004 — Medição de cobertura habilitada

**Onda:** 0 · **Categoria:** Testabilidade · **Prioridade:** P2 · **Criticidade:** C2
**Relacionado:** OPS-001.a (CI), OPS-001.b (threshold obrigatório, Onda 1), QC-001/QC-002

## Problema

Não havia como medir cobertura de testes — impossível estabelecer baseline nem detectar regressão de cobertura ao longo das ondas.

## Ação

1. Instalado `@vitest/coverage-v8@3.2.4` (pinado à versão exata de `vitest` já em uso).
2. `vite.config.ts` estendido com bloco `coverage`:
   - provider `v8`
   - reporters `text`, `text-summary`, `html`, `json-summary`, `lcov` (para futuros gates de CI e Codecov)
   - `all: true` (mede também arquivos sem teste)
   - excludes: UI shadcn, cliente Supabase auto-gerado, `main.tsx`, `server/`, `supabase/`, `docs/`, `ops/`
3. Novo script `test:coverage` em `package.json`.
4. `coverage/` adicionado ao `.gitignore`.

**Sem threshold obrigatório nesta onda** — apenas medição. Threshold + gate no CI entra em OPS-001.b (Onda 1) junto de QC-001/QC-002.

## Baseline oficial (execução inicial)

```
All files  |  % Stmts 8.57 | % Branch 60.36 | % Funcs 37.91 | % Lines 8.57
```

Relatórios completos em `coverage/index.html` (não versionado).

## Critérios de aceite

- (a) Provider v8 rodando sem erro ✅
- (b) Baseline registrado nesta ficha ✅
- (c) LCOV/JSON emitidos (habilitam Codecov/PR comment quando desejado) ✅
- (d) Nenhum threshold falhando build (fora de escopo Onda 0) ✅

## Discoveries

- **D-12:** cobertura de statements/lines em ~8,5% reflete alto volume de páginas ainda não testadas — insumo para priorizar QC-001/QC-002.
- **D-13:** OPS-001.a **não** roda coverage por default; adicionar `bun run test:coverage` como step opcional (não bloqueante) fica para OPS-001.b.
- **D-14:** `src/components/ui/**` excluído por ser shadcn scaffold — reavaliar se receber lógica custom.
