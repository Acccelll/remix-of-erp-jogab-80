**Onda:** 2 (OPEN)

**Data:** 2026-07-12
**Escopo:** especifica o script `scripts/sec002/run-sec-002-tests.sh` (a criar em `SEC-002.tests-02.runner-01.materialize-01`, R189+) que executa os 315 arquivos pgTAP gerados por `gen-tests-02.mjs` sob `supabase/tests/sec-002/batch-{B,C,D,E}/` e agrega falhas por `test_id`. **Nenhum `.sh`, `.sql` ou `.mjs` é criado neste changeset**; apenas contrato, CLI, formato de saída, códigos de erro e invariantes. O runner atual **não existe** (`scripts/sec002/` contém apenas `load-apply-map.mjs`, `validate-dri-matrix.mjs`, `verify-wave-2-preconditions.mjs`), portanto esta spec define arquivo novo, não patch.

## 1. Arquivo-alvo futuro

```text
scripts/sec002/run-sec-002-tests.sh
```

Interpretador: `#!/usr/bin/env bash`. Modo estrito: `set -euo pipefail`.

## 2. CLI

```text
run-sec-002-tests.sh [--batch B|C|D|E|all] [--test-id <SEC-002.T-...>] [--json] [--fail-fast] [--dry-run]
```

| Flag | Default | Efeito |
|------|---------|--------|
| `--batch` | `all` | executa apenas `batch-<lote>/*.sql`; `all` = B∪C∪D∪E em ordem alfabética |
| `--test-id` | — | executa exatamente 1 arquivo cujo header `-- test_id:` casa; mutuamente exclusivo com `--batch` |
| `--json` | off | emite resultado agregado em JSON puro em stdout (nada mais) |
| `--fail-fast` | off | aborta após o primeiro `not ok` |
| `--dry-run` | off | lista arquivos que seriam executados; não conecta ao banco |

Sem argumentos = `--batch all` humano-legível.

## 3. Entradas

| Entrada | Uso |
|---------|-----|
| `supabase/tests/sec-002/batch-{B,C,D,E}/*.sql` | arquivos pgTAP gerados por R187 |
| `supabase/tests/sec-002/_lib/{fixtures,jwt,assert}.sql` | includes consumidos pelos arquivos, nunca executados isoladamente |
| `DATABASE_URL` (env) | conexão `psql` obrigatória; ausência = exit `2` `E_MISSING_DATABASE_URL` |

Sem rede fora do `DATABASE_URL`. Sem leitura de segredos além de `DATABASE_URL`.

## 4. Execução por arquivo

Cada arquivo roda isolado via:

```bash
psql "$DATABASE_URL" --single-transaction --set ON_ERROR_STOP=1 \
  -v batch="$BATCH" -v test_id="$TEST_ID" \
  -f "$file"
```

- Uma transação por arquivo; `rollback` final do próprio arquivo garante zero estado residual.
- Timeout duro por arquivo: `30s` via `timeout 30s psql ...`.
- Saída bruta do `psql` capturada em `/tmp/sec002-runner/<batch>/<test_id>.log`.

## 6. Códigos de saída

| Exit | Significado |
|------|-------------|
| `0` | todos os arquivos passaram |
| `1` | pelo menos 1 `not ok` ou timeout |
| `2` | erro de configuração (`E_MISSING_DATABASE_URL`, `E_NO_FILES_FOUND`, `E_INVALID_ARGS`) |
| `3` | violação de bloqueio de escrita (tentativa de tocar arquivo fora de `/tmp/sec002-runner/`) |

## 7. Invariantes (RUN01-1…RUN01-10)

| ID | Invariante |
|----|-----------|
| RUN01-1 | Nenhuma escrita fora de `/tmp/sec002-runner/**` |
| RUN01-2 | Nenhuma criação/alteração de arquivo em `supabase/**`, `src/**`, `docs/**`, `.github/**` |
| RUN01-3 | Cada arquivo pgTAP roda em transação própria com `rollback` final |
| RUN01-4 | Ordem de execução estável: lote `B→C→D→E`, alfabética por nome dentro do lote |
