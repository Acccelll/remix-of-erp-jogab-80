# ARC-002 · Onda 6 · slice-33 — ClientesStateProvider real

## Decisão
Como `ClientesContext` (fachada) expõe também `oportunidades`/`funilEstagios`
(fora do escopo desta fatia), criamos um provider dedicado
`ClientesStateProvider` só para `clientes`+CRUD. A fachada segue intacta e
consumidores continuam usando `useClientesContext()`.

## Alterações
- `src/contexts/clientes/ClientesStateContext.tsx` (novo): roda `useClientesState`
  + query `useClientes`, sincroniza, expõe `clientes`/CRUDs/`clientesLoaded`.
- `src/contexts/AppContext.tsx`: substitui `useClientesState()` por
  `useClientesStateContext()`; remove `setClientes` de `useAppQueries`;
  `dataLoaded` inclui `clientesLoaded`.
- `src/contexts/app/useAppQueries.ts`: remove `useClientes`, `Cliente`,
  `setClientes`, a query e sua contribuição em `dataLoaded`.
- `src/App.tsx`: `<ClientesStateProvider>` montado acima de `<AppProvider>`
  (dentro de `<ObrasProvider>`).

## Validação
- `tsgo --noEmit` sem erros.
- Consumidores existentes (`useClientesContext`, `useApp().clientes/...`)
  continuam funcionando via bridge.
