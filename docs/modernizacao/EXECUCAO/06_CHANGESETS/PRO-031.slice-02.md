# PRO-031 · slice-02 — UI de parametrização por empresa

**Onda:** 07 · **Achado:** PRO-031 · **Depende de:** slice-01 (núcleo puro + repositório local).

## Contexto

Slice-01 entregou o repositório local `empresaParametrizacaoRepo` com
logo e numerações por tipo, testado em Vitest, sem UI nem
consumidores. Este slice pluga a UI mínima para GM configurar
parametrizações direto na página de Empresas.

## Entrega

- `src/components/admin/EmpresaParametrizacaoDialog.tsx`: diálogo com
  campo **Logotipo (URL)** (com prévia + fallback de erro) e editor
  de **numeração por documento** (RDO, Medição, NF, Requisição,
  Contrato, Cotação). Cada linha edita `prefixo`, `padding`,
  `proximo` com prévia formatada; botão **Padrão** limpa a
  customização e volta ao default global. Ler/gravar via
  `empresaParametrizacaoRepo`.
- `src/pages/admin/Empresas.tsx`:
  - Novo botão `Settings2` na coluna de ações da tabela, abre o
    diálogo com o `empresaId` da linha.
  - Estado `paramAlvo` local ao `CardEmpresas`.

## Regras respeitadas

- Acesso GM: a página `AdminEmpresas` já rejeita não-GM via
  `Navigate` — o diálogo herda a proteção sem duplicar checagem.
- Persistência apenas local (`localStorage`), mesmo modelo do
  slice-01. Nenhum campo é enviado ao backend.
- Isolamento por `empresaId`: escritas não afetam demais empresas
  (garantido pelo repositório e coberto por teste em slice-01).

## Fora de escopo

- Migração de call-sites (RDO/Medição/NF etc.) para consumir
  `emitirNumero` — entra em `slice-03`.
- Upload de logotipo (só URL por ora): decisão pendente de bucket em
  `storage/`.
- Sincronização multi-dispositivo (backend).

## Validação

- `bunx tsgo --noEmit` — limpo.
- Testes do slice-01 permanecem 7/7 verdes (repositório inalterado).
