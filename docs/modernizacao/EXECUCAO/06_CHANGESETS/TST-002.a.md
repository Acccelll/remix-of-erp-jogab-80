# TST-002 — Testes de integração da camada de dados

**Onda:** 3  
**Achado:** TST-002  
**Status:** concluído (baseline)

## Contexto

A camada `src/lib/repositories/*` era a fronteira entre UI e Supabase, mas não tinha testes garantindo o contrato de query (tabela certa, encadeamento certo, `data`/`error` tratados). Uma refatoração descuidada podia trocar `.select` por `.insert` ou engolir erros sem alarme.

## Mudanças

- Novo arquivo `src/lib/__tests__/integracao/repositories-contrato.test.ts` com mock do cliente Supabase que **grava** cada `from(...).op(...)` e devolve resultado configurável.
- Cobertura inicial: `obrasRepo` (listResumo/getById/create/update/remove) e `fornecedoresRepo` (listResumo/create).
- Estilo espelha os demais testes de integração (`cadeias-valor.test.ts`, `cadeias-criticas.test.ts`), sem subir banco.

## Validação

- `bunx vitest run src/lib/__tests__/integracao/repositories-contrato` → 9/9 passando.

## Critérios TST-002

- (a) Mecanismo de teste de integração para repositories ✅
- (b) Contrato de query verificado (tabela + ops + unwrap) ✅
- (c) Erros do Supabase propagam ✅
- (d) Baseline mínimo (2 repositories) ✅
