**Escopo:** materializar, em conteúdo canônico versionado neste documento, o utilitário `scripts/sec002/parse-apply-id.mjs` usado pelo workflow `sec002-pr-checklist` para extrair um único `APPLY_ID` do título/corpo do PR. **Nenhum arquivo em `src/`, `supabase/functions/` ou `supabase/migrations/` é alterado.** A gravação física permanece bloqueada até a abertura formal da Onda 2.

## 1. Racional

R50 consolidou o workflow final de 11 gates e exigiu que o `APPLY_ID` seja parseado uma única vez, propagado por `$GITHUB_ENV` e reutilizado por todos os gates. Sem um parser canônico, cada validador poderia reinterpretar o título/corpo do PR, gerando divergência entre `validate-pr-checklist`, `validate-changed-files`, go/no-go, DRI, acceptance e evidência.

Este changeset congela o parser mínimo, determinístico e sem dependências externas.

## 2. Contratos externos

- **Entrada:** variáveis de ambiente `PR_TITLE` e `PR_BODY`.
- **Formato do título:** `[SEC-002][apply:<apply-id>] <descrição>`.
- **Formato do corpo:** linha `- sec002_apply_id: <apply-id>` ou `sec002_apply_id: <apply-id>`.
- **Fonte de applies:** `import { getApply } from "./load-apply-map.mjs"`.
- **Saída OK:** somente `<apply-id>` em `stdout`, sem prefixos, para uso em command substitution.
- **Saída FAIL:** `[sec002/parse-apply-id] FAIL - <motivo>` em `stderr`.
- **Exit codes:** `0` OK, `1` violação de contrato, `2` erro operacional inesperado.
- **Sem rede, sem secrets, sem escrita em disco.**

## 3. Artefato — `scripts/sec002/parse-apply-id.mjs`

**Caminho de destino:** `scripts/sec002/parse-apply-id.mjs`  
**Encoding:** UTF-8, LF, sem BOM. ESM puro. Node ≥ 20.

```js
#!/usr/bin/env node
// Parser determinístico do apply_id para o workflow sec002-pr-checklist.
// Consome scripts/sec002/load-apply-map.mjs. Nunca lê o apply-map JSON diretamente.
import { getApply } from "./load-apply-map.mjs";

const NAME = "sec002/parse-apply-id";

function fail(message) {
  console.error(`[${NAME}] FAIL - ${message}`);
  process.exit(1);
}

function opError(message) {
  console.error(`[${NAME}] FAIL - OP: ${message}`);
  process.exit(2);
}

try {
  const title = process.env.PR_TITLE || "";
  const body = process.env.PR_BODY || "";

  if (!title.trim()) fail("PR_TITLE ausente");
  if (!body.trim()) fail("PR_BODY ausente");

  const titleMatch = title.match(/\[SEC-002\]\[apply:([A-Za-z0-9_-]+)\]/);
  if (!titleMatch) {
    fail("título deve conter [SEC-002][apply:<apply-id>]");
  }
  const titleApplyId = titleMatch[1];

  const bodyMatches = [...body.matchAll(/^\s*-?\s*sec002_apply_id:\s*([A-Za-z0-9_-]+)\s*$/gm)];
  if (bodyMatches.length === 0) fail("sec002_apply_id ausente no corpo do PR");
  if (bodyMatches.length > 1) fail(`sec002_apply_id duplicado no corpo (${bodyMatches.length})`);
  const bodyApplyId = bodyMatches[0][1];

  if (titleApplyId !== bodyApplyId) {
    fail(`apply_id divergente: título=${titleApplyId}, corpo=${bodyApplyId}`);
  }

  try {
    getApply(titleApplyId);
  } catch (error) {
    fail(`apply_id desconhecido no apply-map: ${titleApplyId} (${error.message})`);
  }

  process.stdout.write(`${titleApplyId}\n`);
  process.exit(0);
} catch (error) {
  opError(error.message);
}
```

## 6. Integração com `sec002-pr-checklist`

Step canônico já congelado por R50:

```yaml
- name: Parse apply id
  id: parse
  shell: bash
  run: |
    set -euo pipefail
    APPLY_ID="$(node scripts/sec002/parse-apply-id.mjs)"
    echo "apply_id=${APPLY_ID}" >> "$GITHUB_OUTPUT"
    echo "APPLY_ID=${APPLY_ID}" >> "$GITHUB_ENV"
```

Contrato de propagação:

1. nenhum gate posterior reparseia `PR_TITLE` ou `PR_BODY`;
2. todos os paths auditáveis usam `${APPLY_ID}`;
3. se este step falhar, os 11 gates não rodam;
4. `validate-pr-checklist.mjs` ainda valida o corpo completo, mas não redefine o id operacional do job.
