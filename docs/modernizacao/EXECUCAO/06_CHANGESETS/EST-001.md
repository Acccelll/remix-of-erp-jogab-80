# EST-001 — Rollback em mutações otimistas legado

- **Achado:** EST-001 (P1, LOTE, Onda 3)
- **Categoria:** Estado / Fluxo de dados
- **Módulos:** M1, M9, M10, M13
- **Referência:** [Etapa 07 — Estado e Fluxo de Dados](../../GOVERNANCA/01_AUDITORIA/ETAPA_07_ESTADO_FLUXO_DADOS.md)

## Contexto

Hooks legados em `src/contexts/app/*` aplicavam mutações otimistas (`setX` antes do `await api.*`) sem restaurar o estado local se a chamada remota falhasse, e vários caminhos apenas logavam `console.error` — o usuário via a mudança persistir na UI mesmo em falha (silenciosa).

## Mudanças

- `useOportunidadesState`: `updateOportunidade` e `deleteOportunidade` passam a capturar snapshot, restaurar em erro e emitir `toast.error` com sufixo "revertida".
- `useColaboradoresState`: `deleteColaborador` idem.
- `useFuncoesState`: `updateFuncao` idem.
- `usePatrimoniosState`: `updatePatrimonio` e `deletePatrimonio` idem.
- `useVeiculosState`: `updateVeiculo` e `deleteVeiculo` idem.

Padrão adotado (uniforme):

```ts
let snapshot: T[] = [];
setState((p) => { snapshot = p; return next(p); });
try { await api.mutate(...); }
catch (e) {
  console.error(...);
  setState(snapshot);
  toast.error("... revertida.");
}
```

## Critérios de aceite

- [x] Toda mutação otimista dos hooks legado listados tem rollback + toast.
- [x] Nenhum caminho `catch` fica apenas com `console.error`.
- [x] Tipagens preservadas (sem `any`); `tsgo` verde.
- [x] Comportamento em sucesso inalterado.

## Riscos

- Baixo: snapshot em memória apenas durante o request; sem regressão em fluxos de sucesso.

## Fora do escopo

- Migração para React Query / repositories (tratada em ondas posteriores).
