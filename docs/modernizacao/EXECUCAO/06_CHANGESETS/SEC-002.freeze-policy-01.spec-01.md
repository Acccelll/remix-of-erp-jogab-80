# SEC-002.freeze-policy-01.spec-01 — Política formal de congelamento de schema

**Onda:** 2 (preparatória — bloqueada por fechamento de `SEC-001`)  
**Data:** 2026-07-12  
**Escopo:** especifica formalmente as regras, exceções, processo de aprovação e enforcement automático (CI) para o **congelamento de schema** durante toda a `SEC-002`, expandindo §8 de `SEC-002.release-plan-01`. Nenhuma migração é aplicada; nenhum código de `src/` ou edge function muda. É pré-requisito para abrir o PR de `SEC-002.helpers-02.migration`.

## 1. Janela do freeze

- **Início:** merge do PR de `SEC-002.helpers-02.migration`.
- **Fim:** 24 h após `SEC-002.batch-E.migration` estável em produção (§9 do release-plan), confirmadas as condições de handoff.
- **Duração estimada:** ~7–10 dias corridos, dependendo das janelas de 24 h.

Fora dessa janela, esta política não se aplica.

## 2. Proibições absolutas (bloqueio automático de PR)

Durante o freeze, nenhum PR pode conter, sob qualquer justificativa exceto §3:

1. `CREATE TABLE` em `public`.
2. `DROP TABLE` em `public`.
3. `ALTER TABLE ... ADD COLUMN` / `DROP COLUMN` / `RENAME COLUMN` em `public`.
4. `ALTER TABLE ... ALTER COLUMN TYPE` em `public`.
5. `CREATE POLICY` / `DROP POLICY` / `ALTER POLICY` fora dos changesets planejados (`helpers-02`, `batch-B`, `batch-C`, `batch-D`, `batch-E` e suas erratas oficiais).
6. `GRANT` / `REVOKE` em tabelas de `public` fora dos changesets planejados.
7. `CREATE TRIGGER` / `DROP TRIGGER` em tabelas de `public`.
8. `CREATE FUNCTION` / `DROP FUNCTION` em `public` fora dos changesets planejados.
9. `CREATE INDEX` **não** `CONCURRENTLY` em tabela com > 10k linhas.
10. Qualquer mudança em `auth`, `storage`, `realtime`, `supabase_functions`, `vault` (já proibida em regime normal).

Violação ⇒ CI reprova o PR com mensagem `SEC-002-FREEZE: <regra violada>`.

## 3. Permissões durante o freeze

Explicitamente permitido sem exceção:

- `CREATE INDEX CONCURRENTLY` em `public` para mitigar §11 de qualquer lote — deve citar o risco no corpo do PR.
- Alterações em `src/` (frontend, hooks, componentes) que não dependam de novas colunas/tabelas.
- Alterações em edge functions que não alterem schema e não introduzam novas chamadas RPC ausentes.
- Alterações em documentação (`docs/`), configuração de CI, dashboards de observabilidade, memória de segurança.
- Hotfixes de bug em código que **respeitem** as policies vigentes.
- Erratas dos changesets planejados (`SEC-002.<lote>.migration.spec-02`, etc.), seguindo o mesmo gate.

## 4. Exceções formais

Toda exceção exige, cumulativamente:

1. Documento `docs/modernizacao/EXECUCAO/06_CHANGESETS/SEC-002.freeze.exception-<n>.md` seguindo o template §7.
2. Aprovação explícita do GM Cappucceno registrada no documento (assinatura + timestamp).
3. Aprovação técnica do tech lead backend registrada no mesmo documento.
4. Menção no canal `#incidentes` **antes** do merge.
5. Rerun completo da suíte `SEC-002.tests-02.suite` em staging **após** o merge da exceção, verde.
6. Registro no changelog do release-plan (`SEC-002.release-plan-01` §12 — adicionar seção "Exceções aprovadas" na primeira exceção).

Exceções são numeradas sequencialmente (`exception-01`, `exception-02`, …) sem reuso.

## 5. Enforcement automático (CI)

Job obrigatório `sec002-freeze-guard` adicionado ao pipeline principal, gatilho: qualquer PR aberto após o merge de `helpers-02` e antes do fim do freeze.

Verificações executadas:

1. **Feature flag `sec002_freeze_active`.** Job lê `.github/sec002-freeze.json` (mantido pelo DRI). Se `active=false`, job passa direto. Se `true`, executa §5.2–§5.5.
2. **Diff SQL.** Para cada arquivo em `supabase/migrations/**.sql` adicionado no PR, roda regex/AST checando as proibições §2.1–§2.8.
   - Exceção: se o nome do arquivo casa `sec_002_(helpers_02|batch_[bcde]|tests_02).*\.sql`, é changeset planejado — passa.
   - Exceção: se o PR contém arquivo `docs/modernizacao/EXECUCAO/06_CHANGESETS/SEC-002.freeze.exception-*.md` aprovado (`approved: true` no frontmatter), passa.
3. **Diff `src/integrations/supabase/types.ts`.** Se houver mudança neste arquivo sem migration planejada correspondente, reprovar (indica schema alterado por outro caminho).
4. **Diff `docs/modernizacao/EXECUCAO/06_CHANGESETS/`.** Nenhuma edição em specs já mergeadas de `SEC-002.*` é permitida — apenas novos arquivos (`spec-02`, `errata-01`, `exception-<n>`) ou o próprio `SEC-001.README.md` (índice).
5. **Snapshot de policies.** Compara `pg_policies` do banco de staging com o baseline capturado antes de `helpers-02`. Qualquer diff fora dos changesets planejados reprovar.

Reprovação bloqueia o merge — override só via `sec002_freeze_active=false` (encerramento formal do freeze) ou exceção §4.

## 6. Feature flag `sec002_freeze_active`

Arquivo canônico: `.github/sec002-freeze.json`.

```json
{
  "active": true,
  "started_at": "<iso8601 do merge de helpers-02>",
  "ended_at": null,
  "current_batch": "B" | "C" | "D" | "E" | "none",
  "dri": "cappucceno",
  "notes": "<opcional>"
}
```

- `active: true` mantido do início do freeze até 24 h após `batch-E` estável.
- `ended_at` só é preenchido pelo DRI, após confirmar handoff §9 do release-plan.
- Mudanças neste arquivo exigem PR com aprovação do GM.

## 8. Interação com hotfixes de segurança externos

Se surgir CVE crítico em dependência **durante** o freeze:

1. Upgrade da dependência é **permitido sem exceção** — freeze cobre schema/policies, não `package.json`.
2. Se o upgrade forçar mudança de schema, aplica-se §4 (exceção formal).
3. CVE em código próprio que exija nova policy ⇒ tratar como errata (`spec-02`) do lote correspondente, não como exceção.

## 9. Comunicação

- **Início do freeze:** mensagem em `#anuncios` com data prevista de fim, canal de dúvidas e link para esta spec.
- **Cada exceção aprovada:** mensagem em `#anuncios` com número, escopo e link.
- **Fim do freeze:** mensagem em `#anuncios` com resumo (nº de exceções, dias de duração real, estado dos dashboards).

## 10. Invariantes do documento

- [ ] Nenhuma proibição §2 é relaxada fora de exceção formal §4.
- [ ] CI job `sec002-freeze-guard` §5 configurado antes do merge de `helpers-02`.
- [ ] Feature flag `.github/sec002-freeze.json` §6 versionada.
- [ ] Exceções numeradas sequencialmente, sem reuso.
- [ ] Freeze cobre `public` — nunca é usado para tocar `auth`/`storage`/etc., que seguem proibições permanentes.
- [ ] Fim do freeze condicionado ao handoff §9 do release-plan, não a data fixa.

## 11. Impacto em produção

**Nenhum neste changeset.** Documento de política operacional. A ativação real (CI job, feature flag, comunicação) é entregue por PR de operação separado, consumindo esta spec como contrato.
