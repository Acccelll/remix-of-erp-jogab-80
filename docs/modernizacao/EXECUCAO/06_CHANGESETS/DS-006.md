# DS-006 — Fonte única de moeda BRL

**Onda:** 4 — Padronização  
**Data:** 2026-07-11  
**Tipo:** STD  
**Escopo:** consolidação transversal de formatação monetária.

## Antes

- 15 arquivos formatavam BRL inline com `n.toLocaleString("pt-BR", { style: "currency", currency: "BRL" })`, com variantes de `minimumFractionDigits` (0/2/4) e `maximumFractionDigits` divergentes.
- Existiam três origens paralelas: `src/lib/currency.ts` (helpers de máscara), `src/lib/money.ts` (arredondamento + `fmtCurtoBRL`) e cópias locais em telas (`fmtBRL`, `brl`, `formatCurrency`).
- Comportamento para nulos/`NaN` era inconsistente: alguns retornavam `""`, outros `"—"`, outros lançavam.

## Depois

- `src/lib/currency.ts` passa a expor `formatBRL(n, { minDigits?, maxDigits?, fallback? })` como **fonte única** de formatação BRL do app.
- Contrato do helper:
  - aceita `number | string | null | undefined`;
  - fallback padrão para `null`/`undefined`/`NaN` é `"—"` (configurável);
  - `minDigits`/`maxDigits` padrão `2`/`2`.
- Todos os call-sites com `toLocaleString(... "BRL" ...)` fora de `currency.ts` foram removidos e passam por `formatBRL`.
- Helpers locais (`fmtBRL`, `brl`, `formatCurrency`) foram mantidos como aliases finos que apenas delegam para `formatBRL`, preservando o diff mínimo nas telas.
- `src/lib/money.ts` continua responsável por precisão (`round2`, `round4`, `sumMoney`) e por `fmtCurtoBRL` (formato compacto `R$ 1,2M`), que tem propósito distinto.

## Validação

- `rg -n "toLocaleString.*BRL|style: \"currency\", currency: \"BRL\"" src` retorna zero ocorrências fora de `src/lib/currency.ts`.
- `bunx tsgo --noEmit` verde.
- Suíte unit continua verde (baseline 437, sem regressão em `money.test.ts`).

## Risco e rollback

- Risco baixo: mudança de formatação puramente apresentacional, sem impacto em cálculos.
- Um efeito visível: valores nulos passam a mostrar `"—"` de forma consistente (antes alguns exibiam string vazia). Onde o call-site quiser suprimir o fallback, basta passar `{ fallback: "" }`.
- Rollback: restaurar os helpers locais para o corpo original com `toLocaleString`. Nenhuma migração de dados envolvida.
