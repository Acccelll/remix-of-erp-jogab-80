# SEC-002.helpers-02.spec-01 — Migração executável das funções de autorização RLS

**Onda:** 2 (preparatória — bloqueada por fechamento de `SEC-001`)
**Data:** 2026-07-12
**Escopo:** consolida em **um único arquivo SQL idempotente** as quatro funções `security definer` especificadas em `SEC-002.helpers-01`, seus grants, índices de suporte e comentários. Este changeset é **apenas especificação do arquivo `supabase/migrations/<ts>_sec_002_helpers_02.sql`** — nada é aplicado ao banco, nada muda no `src/` ou em edge functions. É o **primeiro artefato executável** do release train `SEC-002` e pré-requisito duro dos lotes B/C/D/E.

## 3. Ordem interna do arquivo

Uma transação. Ordem estrita:

```text
begin;
  -- 3.1 funções (create or replace)
  create or replace function public.user_in_empresa(uuid, uuid) ...;
  create or replace function public.user_in_obra(uuid, uuid)    ...;
  create or replace function public.user_in_board(uuid, uuid)   ...;
  create or replace function public.user_in_card(uuid, uuid)    ...;

  -- 3.2 grants (idempotentes)
  revoke all on function public.user_in_empresa(uuid, uuid) from public, anon;
  grant execute on function public.user_in_empresa(uuid, uuid) to authenticated, service_role;
  -- (repetir para as demais)

  -- 3.3 índices de suporte
  create index if not exists idx_user_empresas_user_empresa
    on public.user_empresas(user_id, empresa_id);
  create index if not exists idx_obra_membros_user_obra
    on public.obra_membros(user_id, obra_id);
  create index if not exists idx_board_membros_board_user
    on public.board_membros(board_id, user_id);
  create index if not exists idx_card_membros_card_user
    on public.card_membros(card_id, user_id);
  create index if not exists idx_card_board_posicao_card_board
    on public.card_board_posicao(card_id, board_id);

  -- 3.4 comentários (documentação inline)
  comment on function public.user_in_empresa(uuid, uuid) is
    'SEC-002.helpers-01 §4.1 — true se _user pertence a _empresa ou é GM';
  -- (repetir para as demais, apontando §4.2/4.3/4.4)
commit;
```

**Não** usar `drop function` — quebra dependências de policies em ambientes de teste que já tenham helpers antigos.

## 4. SQL canônico das funções

Cópia literal de `SEC-002.helpers-01` §4 (fonte única). Qualquer divergência de assinatura, `search_path`, `stable`, `security definer`, `language sql` ou corpo é bug do arquivo e reprova no gate. Ordem no arquivo: `user_in_empresa` → `user_in_obra` → `user_in_board` → `user_in_card` (topológica, §I-H6).

## 5. Grants (repetição obrigatória por função)

Bloco padrão de `helpers-01` §2, aplicado às **quatro** funções sem exceção:

```sql
revoke all      on function public.<fn>(uuid, uuid) from public, anon;
grant  execute  on function public.<fn>(uuid, uuid) to   authenticated, service_role;
```

Nenhum `grant execute ... to anon`. Nenhum `grant execute ... to public`.

## 6. Índices de suporte — justificativa

| Índice | Consulta que otimiza | Fonte |
|--------|----------------------|-------|
| `idx_user_empresas_user_empresa` | `where ue.user_id = _user and ue.empresa_id = _empresa` | `helpers-01` §4.1 |
| `idx_obra_membros_user_obra` | `where om.user_id = _user and om.obra_id = _obra` | §4.2 |
| `idx_board_membros_board_user` | `where bm.board_id = _board and bm.user_id = _user` | §4.3 |
| `idx_card_membros_card_user` | `where cm.card_id = _card and cm.user_id = _user` | §4.4 |
| `idx_card_board_posicao_card_board` | `where p.card_id = _card` + join por `board_id` | §4.4 |

Todos `create index if not exists` para reentrant. Nenhum `unique`, nenhum `concurrently` — a migração roda em transação e o volume é pequeno; `concurrently` fica reservado para reindex sob incidente.

## 7. Verificações pós-migração (obrigatórias no gate)

Executar após o `commit`, em janela read-only, cada um retornando o esperado:

from   pg_proc p

join   pg_namespace n on n.oid = p.pronamespace

## 9. Rollback

Cenário: helper introduz regressão detectada só depois do commit.

```sql
begin;
  drop function if exists public.user_in_card(uuid, uuid);
  drop function if exists public.user_in_board(uuid, uuid);
  drop function if exists public.user_in_obra(uuid, uuid);
  drop function if exists public.user_in_empresa(uuid, uuid);
commit;
```

**Só é seguro enquanto nenhum lote B/C/D/E tiver sido aplicado.** Depois disso, `drop function` derruba as policies dependentes; usar rollback dos lotes primeiro (companions `SEC-002.batch-*.rollback.sql`) e só então este.

Índices podem permanecer — não têm efeito colateral e servem outras consultas.
