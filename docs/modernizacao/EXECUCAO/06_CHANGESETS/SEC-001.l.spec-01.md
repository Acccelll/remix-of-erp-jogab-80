# SEC-001.l.spec-01 — Logout aguardado, limpeza de sessão local e invalidação de cache RBAC

**Onda:** 2 (bloqueada — D-1/D-2 · apoio D-9 autorizado)
**Data:** 2026-07-12
**Escopo:** especifica o `logout` canônico pós-cutover: sequência determinística, aguardada (`await`), com limpeza explícita de Auth (Cloud) + `localStorage` + cache RBAC in-memory. **Nenhum código de produção é alterado neste changeset.**

## 1. Problema (recap audit-02 §4/§8)

Hoje `AppContext.logout`:

1. `setCurrentPlayer(null)`
2. `supabase.auth.signOut()` **sem `await`**
3. não limpa entradas específicas de `localStorage` (perfis, cache de RBAC, drafts de mobilização provisória)
4. não invalida `has_role` cache (quando existir — ver `SEC-001.k`)

Consequências:

- Race: nova navegação pode ler `supabase.auth.getSession()` ainda válido e renderizar UI "logado" por milissegundos.
- `isGM` residual em memória se o próximo login for de outro usuário na mesma aba antes do `signOut` completar.
- `localStorage` mantém dados de negócio do usuário anterior (violando isolamento por usuário).

## 2. Estado alvo

`AppContext.logout` canônico:

```
async function logout() {
  try {
    await supabase.auth.signOut({ scope: "local" });
  } finally {
    invalidateRbacCache();              // SEC-001.k
    clearScopedLocalStorage();          // ver §3
    setCurrentPlayer(null);
    navigate("/login", { replace: true });
  }
}
```

Invariantes:

- `await` obrigatório em `signOut`.
- `setCurrentPlayer(null)` **depois** do `signOut` — evita janela em que UI acha que está deslogado mas token ainda válido em outra aba.
- `scope: "local"` para não invalidar sessão de outras abas/dispositivos sem intenção explícita (logout global é feature separada, fora deste changeset).
- Bloco `finally` garante limpeza mesmo se `signOut` lançar.

## 3. `clearScopedLocalStorage()`

Remove apenas chaves de dados de usuário/sessão. **Não** toca em chaves globais de app (tema, feature flags, últimos filtros anônimos).

Chaves alvo (levantamento inicial — a lista final vira `SEC-001.l.audit-01`):

- `gestaobra.perfis.cache`
- `gestaobra.rbac.cache`
- `gestaobra.mobilizacao.draft.*`
- `gestaobra.currentPlayer`
- `sb-<project>-auth-token` (redundante ao `signOut`, mas defensivo)

Chaves preservadas:

- `gestaobra.ui.theme`
- `gestaobra.ui.sidebar.collapsed`
- `gestaobra.column-filters.*` (visibilidade de colunas — preferência local, não sensível)

## 4. `invalidateRbacCache()`

Depende de `SEC-001.k` (RBAC server-sourced com cache in-memory por sessão). Contrato:

- Zera o cache in-memory de `has_role`.
- Cancela promises pendentes de fetch RBAC.
- Emite evento `rbac:invalidated` para hooks que dependem de re-fetch.

Se `SEC-001.k` ainda não estiver em produção no momento de aplicar `SEC-001.l`, `invalidateRbacCache()` é no-op documentada.

## 5. Multi-aba

`supabase.auth.signOut({ scope: "local" })` não propaga para outras abas. Comportamento aceito neste changeset. Propagação cross-tab (via `BroadcastChannel` ou `storage` event) fica como `SEC-001.m` opcional, não bloqueante.

Racional: logout global multi-aba tem custo de UX (usuário perde trabalho em outras abas) e não é requisito de segurança levantado por audit-02. Mantido fora.

## 6. Testes de aceitação

1. `await logout()` retorna somente após `supabase.auth.getSession()` resolver `null`.
2. Após `logout()`, `localStorage.getItem("gestaobra.currentPlayer")` === `null`.
3. Após `logout()`, `localStorage.getItem("gestaobra.ui.theme")` **preservado**.
4. Login → logout → login com outro usuário: `currentPlayer.isGM` reflete apenas o segundo usuário (sem residual do primeiro).
5. `signOut` lançando erro simulado: `currentPlayer` ainda vira `null` e navegação para `/login` ocorre (bloco `finally`).
6. Nenhuma chamada a `has_role` retorna valor cacheado do usuário anterior após `logout()`.

## 7. Fora de escopo

- Logout global multi-dispositivo (`scope: "global"`).
- Propagação cross-tab automática.
- Rotação de refresh token (já coberta por config Cloud padrão).
- Purge de IndexedDB (não usado hoje pelo app).

## 8. Ordem no trem de release

- **R7** (pós `SEC-001.k`): aplicar `SEC-001.l` — logout aguardado + limpeza + invalidação RBAC.
- Dependência dura: `SEC-001.k` precisa ter definido `invalidateRbacCache()` (mesmo que como export de no-op inicial).
